# 文章 / 周报 → 滴答清单（MCP 版）

将技术周报中的推荐文章批量转换为滴答清单待办，或把单篇文章一键加入待办，自动完成分类与标签。

**本技能全程只使用 dida365 MCP 工具，不依赖任何本地脚本、URL Scheme 或操作系统命令，Windows / macOS / Linux 行为完全一致。** 执行任何写入前必须先向用户展示预览并得到确认。

## 前置：解析清单映射

工作流开始前，调用 `list_projects` 获取用户当前的清单列表：

- **清单名 = 二级分类**。整理文章时只能使用用户已有的清单名，不得凭空发明分类。
- 某篇文章明显不属于任何现有清单时：**停下来询问用户**（列出该文章和建议的新清单名），等用户在滴答清单中建好清单或指定归入某个现有清单后再继续。
- 用户未提供任何偏好时，标签（三级分类）可自由命名，无需确认。

## 标准整理格式

收到周报批量内容后，先整理为如下结构再执行：

```markdown
## 清单名（= 用户滴答清单中已有的清单）

### 标签（自由命名）

**[文章标题](文章链接)**

- 推荐语（沿用周报原文的推荐语句，或自行概括 20~50 字）
- 出自：来源周报名称
```

规则：每篇文章必须有「出自」行；文章块之间不加分隔线；标题保留 `[标题](链接)` 格式以便预览时核对。

## 字段映射（写入 MCP 时）

| 滴答清单字段 | 来源 | 说明 |
|---|---|---|
| `title` | 文章标题（纯文本，不含 markdown 链接语法） | 链接不要写进标题 |
| `content` / `desc` | 推荐语 + `出自：来源` + 文章链接 | 多条目用换行合并 |
| `projectId` | 清单名 → 用 `list_projects` 的返回结果按名称精确匹配解析为 ID | 匹配不到时暂停询问，不要静默落入收集箱 |
| `tags` | 三级分类 | 先 `list_tags` 检查，缺失时用 `create_tag` 创建 |

## 工作流分支 A：批量周报

1. **接收**：用户提供周报原文（粘贴文本或文件路径）。
2. **整理**：按「标准整理格式」输出；遇到未知分类按前置规则暂停询问。
3. **预览**：把整理结果以表格形式展示给用户（标题 / 清单 / 标签 / 链接），**等待明确确认**。
4. **执行**：用 `batch_add_tasks` 一次性批量创建。不要在任务里设优先级，除非用户明确要求（且注意 priority 必须是 JSON 数字）。
5. **复核**：执行后调用 `list_undone_tasks_by_time_query` 或按清单抽查，向用户汇报成功条数与失败明细。

## 工作流分支 B：单篇文章

1. **接收**：文章 URL + 标题（缺标题则从 URL 推断或询问）。
2. **判断**：推断清单和标签，生成一句 20~50 字推荐语；清单不确定时先告知判断结果让用户确认。
3. **预览**：展示将创建的任务字段，等确认。
4. **执行**：用 `create_task` 创建，`content` 中包含 `出自：{文章URL}`。

## 注意事项

- 所有写操作遵循 dida365 技能的操作守则：先查后改、模糊请求先澄清。
- 创建失败时按 dida365 技能的失败排查处理；日期字段如需设置，偏移量写 `+08:00` 带冒号格式。
- 用户想积累自己的分类体系时，建议其在滴答清单中先建好清单，本技能会在下次运行时通过 `list_projects` 自动识别。
