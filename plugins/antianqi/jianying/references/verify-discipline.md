# 判据纪律（任何"通过"都必须过这一关）

> 这份是**护栏的知识层**。机械部分在 `scripts/` 与 MCP 动词的内建检查里。
> ★ **护城河不在工具，在判据** —— 工具（读草稿/渲染/调色）谁都能调；"怎么知道它真的生效了"是我们独有的。

⇒ **"噪声"大部分是判据的放大，不是画质的崩坏** —— 人眼在 GUI 的连续播放里察觉不到，但逐像素静态比对会把它放大。

**★ 而且非确定性是【逐帧】的**（2026-10-21 §82 实测）：

| 测法 | 结果 |
|---|---|
| 同一草稿渲两遍 | **69/108 帧不同**；frame 001~004 是 MAD≈123 / maxAbs 255 / 95% 像素全变（整帧不同），frame 000/005~009 只差 0.47~1.69 |
| 同一时刻**连着抓两次** | **4/6 时刻像素就不同** ⇒ 非确定发生在"每一次抓帧"这一层，不是"隔一段时间重渲染" |
| 抓到的 ts 与目标 t 的偏差 | **恒为 0** ⇒ **不是抓错帧、不是时间对齐问题** |
| 另一个简单草稿 | **0/6 不确定** ⇒ **不是整个渲染器都不确定**（只是特定时刻/特定素材帧） |

⇒ **判据必须【逐帧】校准**：`bar_i = max(threshold, noise_i × noiseK)`，
**不能用全局最大噪声**（那会把稳定帧的真实改动一起压死 ⇒ 假 FAIL）。
`verify_diff` 的 visibility 维度现在输出 `unstableFrames` / `visibleMaxMad` / `visibleFrame` / `frameDetail[]`。

**★ 顺带澄清两类"对齐"必须分开说**：

| 比什么 | 参照 | 确定性 |
|---|---|---|
| 我们的复刻 **vs 官方 shader** | 本机跑官方 `.frag` shader 的**离线 GL 渲染** | ✅ 确定 ⇒ **≤1 LSB 结论不受影响** |
| 官方渲染帧 **vs 官方渲染帧** | 预览渲染器抓的帧 | ⚠️ 逐帧部分非确定 ⇒ 必须逐帧校准 |

**⇒ 纪律：像素判据必须逐帧校准；没有 `noiseDir` 就标"未校准"，不许装作可信。**

## 三层判定

```
协议层说支持  ≠  契约层被接受  ≠  渲染层生效
```

| 层 | 判什么 | 怎么判 |
|---|---|---|
| **契约层** | 字段认不认 | 材料存活 / 回写明文 / 字段保留 |
| **渲染层** | 有没有效果 | 无头取帧 + **A/B 逐像素差分** + **阳性对照** |

## 六条硬规矩

### 1. 判据的"视野"必须覆盖被测对象
**只抽一帧 = 用抽样代替了被测对象** ⇒ 假 FAIL 和假 PASS 都会出。

实测（2026-10-21）：单帧抽样选的第 5 帧 MAD=0.47（阈值 0.5）判 FAIL，
而同一批帧里第 74 帧 MAD=123.5 / maxAbs=255 / 100% 像素变化。
⇒ **对策：`verify_diff` 一律取全帧最大（max-over-frames）。**

### 2. 阴性对照必须存在
每个"能跑"都要配一个"不能跑"的对照。
实测：官方抽取帧接口**全是预览路径**（ΔYAVG 0.00）⇒ "抽帧里没有调色"是**官方设计**，不是我们的 bug。
**没有阴性对照的 PASS 一律不算 PASS。**

### 3. 输出必须能自证是"这次跑出来的"
**同一输出目录不许并发跑两份验收**（会互相覆盖帧 ⇒ 证据被污染）。
⇒ 每次跑用**独立输出目录**，并在文档里写清目录名。

### 4. 探针要能区分"没生效"和"没在测"
**所有节点数值一模一样 ⇒ 探针没在测单节点。**
（实测踩过：探针用全局 SPEC 而非单节点 spec ⇒ 6 个节点报出完全相同的数。）

### 5. 参数形态不对 ⇒ 静默失效
链的每个节点要么真生效、要么被整段跳过，**不会报错**。
实测踩过：`hsl` 键名写错 ⇒ 节点被跳过，**链看着跑通、实际少一个节点**。
⇒ 对策：**逐节点生效探针内建在动词里**（`grade_apply` 每个节点单开必须产生非零改变，否则判失败）。

### 6. 注入坏了必须失败（negative-injection）
每个判据都要能被"故意弄坏"而失败。已做过的注入：

| 注入 | 期望 | 实测 |
|---|---|---|
| 坏 LUT 维度顺序（.cube 转置） | LUT 误差爆 | 0.000219 → 0.268430（放大 **1223×**） |
| 逐点算子整体压掉 | 逐点误差爆 | 0.000119 → 0.164800 |
| 金字塔接线差一级 | 自洽性爆 | 9.7e-19 → 5.7e-2 |
| 改画质到 0 | 探针爆 | 逐节点探针报"没有生效" |
| 同一目录对同一目录 | 判 FAIL | maxMad=0 ⇒ FAIL ✓ |
| **亮度 −0.01 当噪声** | 校准后判"不可见" | maxMad=5、噪声底=5、判据线=7.5 ⇒ FAIL ✓ |
| **亮度 −0.06 当真改动** | 校准后判"可见" | maxMad=19、倍数 3.8 ⇒ PASS ✓ |
| **白底 +0.2 推到 255** | 必须报"新增削波" | clipΔ=33.33% ⇒ problems 命中 ✓ |
| **expect 说 volume 不该变** | 必须 FAIL | 逐段字段差检出 volume 变化 ⇒ FAIL ✓ |

### 7. ★★ 像素判据必须先量【噪声底】（2026-10-21 实测，最重要的一条）

**官方渲染器不是确定性的。** 同一份草稿**渲染两次**，帧就已经不一样：

| 样本 | 不同的帧 | 最差 MAD | 备注 |
|---|---|---|---|
| 容差 60ms（原始） | 14/108 | **48.19** @frame39 | 整帧不同（maxAbs=255） |
| 容差 20ms（收紧后） | 17/108 | **123.55** @frame73/74 | 整帧不同 |

⇒ **两次渲染的噪声底（≈48~123）比任何"改动可见"阈值（0.5）高两个数量级。**
⇒ **任何裸 MAD 都不能证明"改动可见"** ——包括历史上写进文档的 123.51 @frame74。

**根因**：`jyai-b-render.mjs` 抓帧是"seek 之后轮询 captureFrame，拿时间戳在容差内的第一帧"。
容差 60ms > 半帧周期（83ms）⇒ 会接受**邻近帧**；抓哪一帧取决于调度时序 ⇒ 不确定。
（收紧到 20ms 后 108/108 全部精确命中、兜底 0、丢失 0，**但噪声依旧** ⇒ 噪声不是容差造成的。）

**对策（三选一，按可靠性排序）**：

1. **用语义判据**（推荐）：改草稿链的"生效"证据 = **落盘草稿的逐段字段差**（如 `volume` 0.99→0.2），
   完全不依赖像素，确定性、可复跑。`verify_diff` 的 `checks:['timeline']` + `expect.segmentFieldChanged` 就是这个。
2. **噪声校准**：给 `verify_diff` 传 `noiseDir`（同一状态**再渲染一次**的帧），
   判据线自动抬到 `max(threshold, noiseMad × 1.5)`；不传就在输出里标 `calibrated:false` + note。
3. **用我们自己的渲染器**：`grade_apply` 走的是我们自己的 GL/LUT 链（确定性）⇒ 它的像素差分是可信的。

> **纪律：报"改动可见"之前，先报噪声底。** 没有噪声底就不要报"可见"。

### 8. ★★ 阳性对照必须与被测项【同路径、同对象】，只换一个已知会生效的东西

> 2026-10-22 审计实测：判"官方预览渲染器不执行 effect"时，带 effect 与不带 effect 的两稿
> 逐像素完全相同（看起来是结论）。但把对照换成 `adjust`（已知官方预览**会**应用）后，
> **adjust 也完全相同** ⇒ 装置坏了，结论不成立。
>
> ⇒ **"没变"有三种可能：①真的不支持 ②没生效/没挂上 ③装置坏了**。
> 区分它们只有一个办法：**同一条路径、同一个对象、只换一个已知会生效的东西**，
> 它也"没变" ⇒ 判定装置有问题，换装置再测。

### 9. ★★ 判据的"期望值"必须先在【已知正确的实现】上成立

> 2026-10-22 实测：我拿"改了 R 通道 ⇒ G/B 通道必须逐字节不变"当硬判据，
> 而**官方 curves 语义里 Y（亮度）曲线会等量改 R/G/B 三个通道**（为保色相，这是有意的）。
> ⇒ 那个判据与被测对象语义矛盾 ⇒ 拿它判自己的实现 = **自己判自己失败**。
>
> ⇒ **写判据前先拿"官方明确对齐的那份实现"跑一遍**（比如 curves 的官方布局 spec），
> 看它是否满足你的期望 ⇒ 满足才说明你的期望是对的。

### 10. ★ 噪声底必须【逐帧】，不能用平均 MAD

> 官方预览渲染**非确定**：同一草稿渲两遍，整片平均 MAD 可能是 0.00000，也可能是 0.01602
> （差 1 帧、**maxAbs 255**）⇒ 用平均 MAD 判"是否显著"会**随机翻车**。
>
> ⇒ 用逐帧判据线：`bar_i = max(threshold, noise_i × noiseK)`
> （这一条已经落在 `verify_diff` 的实现里，§82 修正；这里补的是"为什么不能用平均"）

## 数字底线（我们复刻链的验收口径）

| 对象 | 口径 | 实测 |
|---|---|---|
| 调色链（逐点） | maxAbs ≤ **1 LSB** | 1 LSB（hsl_curves / curves / hsl / logWheel / colorCorrection 全部） |
| 调色链（65³ LUT） | maxAbs ≤ **2 LSB** | 2 LSB（对齐 §54 curves 的 65³ precedent 0.0086） |
| 曲线恒等 | **字节完全一致** | 256/256 texel |
| 分级 | 1 = 像素完全相同 | 1 LSB ⇒ 归一到 2 LSB |
| ~~改动可见性~~ | ~~max MAD > 阈值~~ | ⚠️ **作废**（123.51 @frame74 与噪声底同量级 ⇒ 不可信）。改用语义判据或噪声校准 |
| 真草稿 | sha 逐字节相同 | 64 files identical |

## 调色的"生效"判据（三条同时成立才算生效）

1. **逐节点探针**：每个节点单开 ⇒ MAD > 0
2. **全链改变量**：`grade_change_mad > 0`
3. **空间分布合理**：改"亮"应该 mean 上升、**clip 比例不超阈值**（过曝是另一个问题，不是"调亮"）

## 判据自检清单（每次写新判据时问自己）

- [ ] 判据的视野覆盖被测对象了吗？（不是抽一帧）
- [ ] 有阴性对照吗？
- [ ] 故意弄坏它会失败吗？
- [ ] 探针能区分"没生效"和"没在测"吗？
- [ ] 输出能自证是这次跑出来的吗？
- [ ] ★ **像素判据的噪声底量了吗？**（同一状态重渲染 ⇒ 差异有多大？没有噪声底就别报"可见"）
- [ ] ★ **基线是【这次跑】产生的吗？**（借用别的跑的残留目录 ⇒ 测的是两次不同的改动）
