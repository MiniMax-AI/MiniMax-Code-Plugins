# flomo 浮墨 · 保存提醒

## 核心定位

在对话中捕捉那些**用户自己说出来、且未来可能想找回**的片段，整理成 flomo memo 草稿，**确认后再写入**。

这不是自动记忆一切，也不是会议纪要工具。默认只提醒和起草，不擅自写入。保存动作保留用户的主动选择。

配套的回顾整理由 `flomo-daily-echo` Skill 负责，本 Skill 只管写入方向。

## 文件结构

- `SKILL.md`：本文件，稳定协议。
- `profile.md`：共享 profile，包含用户表达画像与已确认偏好。

### 如何定位 profile.md

profile 与本 Skill 同目录，位于插件包的 `skills/flomo-capture/profile.md`。

读取时按运行环境给出的插件安装目录定位该文件并拼接相对路径；若运行环境提供了插件根目录占位符（部分子代理 prompt 中会以 `${PLUGIN_ROOT}` 形式出现），优先使用 `${PLUGIN_ROOT}/skills/flomo-capture/profile.md`。

读取前用只读方式确认文件存在；不存在时按“缺失”处理。

### 写入 profile.md

profile 与本 Skill 同目录，是插件包内的用户自有文件，可直接读写。写入时保持 YAML frontmatter 与正文的完整结构，只替换需要更新的字段，不要重写整个文件。

更新 `Expression Profile` 时**不得**顺手改写已确认的 `User Preferences`。

## 启动检查

生成草稿前先读 `profile.md`，判断状态：

- `missing`：文件不存在。
- `empty`：文件存在但 `profile_status: empty`、`updated_at` 为空或仍是模板占位。
- `invalid`：缺少 `updated_at: YYYY-MM-DD`，或日期无法解析。
- `stale`：`updated_at` 距今超过 30 天。
- `fresh`：`profile_status: generated`、`updated_at` 有效、且无模板占位。

处理规则：

- `fresh`：直接使用。
- `stale`：不阻塞当前任务，完成后提示可刷新。
- `missing` / `empty` / `invalid`：征得用户同意后再初始化；用户拒绝则用保守草稿，并**明确说明这次没有使用个性化画像**。

不得跳过检查直接走 fallback。

fallback 只在下列情况下成立：flomo MCP 不可用、采样失败、无法读写 profile、或用户明确说“别读我的笔记，直接给草稿”。进入 fallback 时必须明说。

## 首次设置

若 `profile.md` 中 `User Preferences / Save Reminder / reminder_mode` 为空，先问一个简短问题，**不要先读取 memo 样本**：

```markdown
你希望 flomo 保存提醒怎么工作？

1. 只在我说“保存/记一下”时使用
2. 我让你扫描当前对话时，帮我挑值得保存的内容
3. 本轮对话里，看到特别值得留的内容可以轻提醒
```

写入 `profile.md` 的 `User Preferences / Save Reminder`：

- `explicit_only`：只在用户明确要求保存时使用。
- `scan_on_request`：用户要求扫描时集中判断。
- `session_light`：本轮会话内允许低频轻提醒。

默认推荐 `scan_on_request`。不要默认开启全局主动提醒。

## 五个保存入口

用于判断“是否值得提醒保存”。它们不是标签，不要写进 memo。

1. **想到什么** —— 灵感、问题、判断、观点、假设、类比。用户把一个想法说清楚了。
2. **感受到什么** —— 情绪、自我觉察、关系中的体感。不只是发泄，而是形成了理解。
3. **经历了什么** —— 日记、生活片段、关系现场。有具体场景、人物或时间感。
4. **读到/听到什么** —— 书、文章、播客、视频、课程。用户把外部内容转成了自己的理解。
5. **做事中学到什么** —— 工作、产品、项目、创作、决策。沉淀出经验、原则或下一步。

## 不提醒场景

不要提醒保存：

- 普通事实问答、纯临时任务或查询结果。
- AI 单方面总结，用户没产生新想法或新表达。
- 情绪还在流动，尚未形成用户愿意留下的表达。
- 只有链接、摘录或信息转述，没有用户自己的反应。
- 同一话题短时间内已提醒过。
- 涉及敏感或第三方隐私，且用户没有明确保存意图。
- 存下来只会增加噪音、未来难以复用。

## 触发前自检

1. 未来用户可能想找回这句话、这个感受或这个问题吗？
2. 这是用户自己的表达，而不是 AI 的发挥吗？
3. 存下来会增加回看的可能性，而不是增加噪音吗？

至少两个为“是”才提醒。

## 上下文来源

优先级：

1. **用户明确指令** —— 用户指定标签、格式、保存目标时优先遵守。
2. **profile.md 的 Expression Profile** —— memo 格式、标签习惯、长度、保存价值判断、草稿风格。
3. **flomo MCP 的 memory 接口** —— 若运行环境提供 `memory_user` / `memory_context`，轻量读取以理解用户语境。memory 是“上下文”，不是“写作风格画像”，不能只凭它决定标签或格式。当前 flomo 官方 MCP 尚未提供 memory 工具，因此这一层通常不可用。
4. **flomo memo 采样** —— 学习真实写法与标签习惯，补足 memory 里没有的具体细节。
5. **冷启动默认** —— 都不可用时，用保守短 memo，不强行打标签。

## 标签策略

标签不由五个入口决定。优先级：

1. 用户明确指定的标签。
2. 相似 memo 中反复出现的标签。
3. profile.md 中记录的高置信常用标签。
4. 目标 memo 内容里自然出现、且用户历史中存在的标签。
5. 置信度不足时，少打或不打。

**禁止为了完整而创造新标签。** 不要在协议里写死某个用户的标签。

## memo 草稿标准

好的草稿应该：

- 短、具体、可搜索。
- 有用户自己的声音，保留关键原话。
- 以后回看仍能理解当时为什么记。
- 不替用户过度拔高，不把 AI 推断写成用户确定判断。

避免：

- 泛泛总结、鸡汤化、过度心理分析。
- 自动加意义、“这说明你很重视……”这类空泛句式。
- 写得太长。
- 像会议纪要或知识库条目。

无样本时的保守默认格式：

```markdown
- 一句话写下值得保存的内容。
- 必要时补充背景、来源或下一步。
```

## 提醒话术

低打扰版本：

```markdown
这句像是可以留在 flomo 里：

>「……」

我可以整理成一条 memo：

……

要保存吗？
```

更轻的版本：

```markdown
这句挺像一条 flomo：

>「……」

要我帮你记一下吗？
```

用户明确说“记一下”“保存到 flomo”时，不再解释判断理由，直接整理并写入。

## 写入规则

**默认不写入。** 只有以下情况写入：

- 用户明确确认“保存”“可以”“记一下”“存到 flomo”。
- 用户已提前授权当前类型内容自动保存。

写入前：

- 先调用 `get_format_guide` 读取 flomo 官方格式规范。flomo 只支持**加粗、高亮、下划线、有序列表、无序列表**，不支持标题、引用、代码块、链接等其他 Markdown 语法。高亮为 `<mark>文字</mark>`，下划线为 `<u>文字</u>`。
- 需要动标签体系时先调用 `get_tag_guide` 了解标签命名与层级规范。
- 标签直接写在正文里（如 `#想法`、`#读书/心理学`）。
- 避免保存未确认的推断；对敏感或第三方隐私保持克制。

写入时调用 `memo_create`，参数 `{"content": "<正文>", "format": "markdown"}`（`format` 可省略，默认 markdown）。正文里的标签会被 flomo 解析成结构化标签。

写入后：

- 返回 memo id。
- 不要额外扩写或自我评价。

## 可用工具速查

以下是 flomo 官方 MCP 暴露的工具，参数以实际 schema 为准：

| 工具 | 用途 | 关键参数 |
| --- | --- | --- |
| `memo_search` | 按关键词、标签或日期范围搜索笔记 | `keywords`（空格分隔=AND，不要用 `|`）、`tag`、`start_date`、`end_date`、`limit`（最多 50）、`has_tag`、`original_only`、`from` |
| `memo_create` | 新建笔记 | `content`（必填）、`format` |
| `memo_update` | 更新已有笔记 | `id`（必填）、`content`、`format`、`local_updated_at` |
| `memo_batch_get` | 按 id 批量取全文 | `ids`（数组或字符串，单次最多 10 条）、`id` |
| `memo_recommended` | 取与某条笔记相关的其他笔记 | `id`（必填）、`limit`、`no_same_tag` |
| `get_daily_review` | 取今日每日回顾推荐的笔记全文 | 无 |
| `tag_tree` | 取标签树与层级 | `prefix`、`depth`、`limit`（最多 1000） |
| `tag_search` | 按名称关键词搜标签 | `keywords`（必填）、`limit` |
| `tag_rename` | 批量重命名标签 | `old_tag`（必填）、`new_tag`（必填）、`max_memos` |
| `get_format_guide` | 取 flomo 正文格式规范 | 无 |
| `get_tag_guide` | 取标签使用规范 | 无 |

使用要点：

- `keywords` 只填检索词，多个词用空格分隔表示 **AND**，**不要用 `|` 表示 OR**。
- 时间范围用 `start_date` / `end_date`，**不要**把“昨天”“最近”这类相对词塞进 `keywords`。
- 返回项若 `content_truncated=true`，说明正文被截断。**修改该笔记前必须先用 `memo_batch_get` 取全文**，否则会覆盖掉丢失的内容。
- `memo_batch_get` 顶层若 `truncated=true` 且有 `omitted_ids`，把 `omitted_ids` 里的 id 再单独调一次。
- flomo 官方 MCP 没有 `memo_delete` 工具。删除笔记必须由用户在 flomo 客户端完成。

## 自动保存边界

自动保存是例外，不是默认。

可以自动保存：用户明确授权的内容类型、用户直接说“以后这类都自动保存”、明确的产品/工作决策、反复出现的个人原则。

不要自动保存：敏感第三方信息、未确认推断、临时情绪、普通问答、低价值摘要。

## 失败处理

- MCP memory 接口不可用 → 跳过 memory，尝试 memo 采样。
- profile 缺失/为空/过期 → 先征得同意再初始化或刷新；只有用户拒绝、采样失败或写回失败后才降级。
- memo 采样不可用 → 说明无法读取样本，给保守草稿，**不伪装已生成画像**。
- 写入工具不可用 → 给出草稿并说明没有写入。
- 格式不确定 → 用保守短 memo，不发明复杂结构。
- 误触发 → 用户没回应就继续，不要追问。

## Profile 初始化与刷新

生成或刷新 Expression Profile 时，按顺序采样真实 flomo 数据：

1. 最近 3-6 个月随机 memo：可用时取 20-50 条。
2. 最近 7-14 天 memo：可用时取 5-10 条。
3. 每日回顾、历史推荐或相关旧 memo：可用时取 3-5 条。
4. 被其他 Skill 调用时，可按当前话题补充 3-5 条相关样本。

不要只读最近几条 —— 容易被临时项目、情绪或话题污染。

学习维度：

- 是否用标签，标签在开头还是结尾。
- 常见标签层级，哪些宽标签应避免滥用。
- 常见长度：一句话、短段落、bullet，还是较长反思。
- 是否保留用户原话。
- 是否记录时间、场景、人物、来源或下一步。
- 语气是口语、克制、反思、决策导向，还是正式。
- 用户倾向保存什么，什么只是噪音。

刷新 Expression Profile 时**不得**顺手改写已确认的 User Preferences。

写入或刷新后，简短说明：`updated_at`、采样窗口、样本数量、这次学到或改动了哪些维度。
