# 配图与素材 SOP

> 来源:2026-09-17 端到端实测沉淀(用户硬要求)。核心原则一句话:
> **遇到主体不全 / 半截 / 比例差的图,先去搜有没有全貌的,别硬裁、别硬用。**

## 1. 取图路径(按优先级)

| 路径 | 做法 | 适用 | 实测 |
|---|---|---|---|
| **A · 官方渠道** | 官方 brand kit / simple-icons(curl 可取);产品截图截官方 help/文档;数据用官方报告 | logo、产品图、数据 | ✅ 合规最强,事实性题材尽量停在这级 |
| **B · 官方站点直取(成功率最高)** | `node <技能>/scripts/fetch-official-images.mjs <官网URL>` 列出候选图(含 CSS 背景图与懒加载图)→ 挑序号 → `--get 1,3 --out-dir assets` 下载。**站点要登录/滚动加载、脚本打不开时,用 agent 内置浏览器 inspect DOM 拿到图片 URL,再 `--url <URL>[,<URL>...] --out-dir assets` 落盘**(同一套 host/重定向/大小/文件名校验,且不需要 Playwright);工具会标注"非本站域名"的可疑资源,并可直接接 `prep-image.mjs --check` | 品牌 logo、产品图、hero 图、CEO 头像、新闻图 | ✅ 实测 minimaxi.com 6/6 全相关 |
| **C · Wikipedia Commons / CC** | 搜历史人物、地标、公共机构 | 历史题材 | ✅ 一次下载永久复用,合规零风险 |
| **D · 公告与权威报道截图** | **负面事件题材**(暴雷 / 处罚 / 诉讼 / 争议):官网不可能提供这类素材,A/B 必然落空 —— 素材的正确来源是**事件本身的一手载体**:交易所公告、监管文书、公司官方声明/致歉信 > 媒体报道页(一线权威与腾讯新闻/新浪等主流门户均可,自媒体除外)。用内置浏览器或 Playwright 打开后**截图**(命令见下) | 暴雷、监管处罚、诉讼、翻车/争议 | ✅ 报道性引用;截图必须保留媒体名与日期 |
| ~~旧 · Bing 图搜~~ | image-downloader 技能 | — | ❌ 中文冷门题材 5/5 全无关(反爬拦截页 + "猜你喜欢"推荐卡),**默认不用** |

**用内置浏览器 inspect 时的纪律**(站点需要交互、脚本打不开时走这条路):

1. **拿到图片 URL 后不要用浏览器"另存"或让它硬下**:交给 `--url` 落盘,才走得到 host 白名单/重定向逐跳复核/30MB 上限/文件名清洗/不覆盖这套纪律。
2. **别把"打开新页面"当刷新**:宿主浏览器里 `navigate(replaceCurrentTab)` 常常是开新标签(带 IDB 的站点数据会看着"凭空消失"),要重载就 reload / F5。
3. **批量动作用脚本,别让浏览器扛**:连续点击 15+ 次或批量下载会触发站点的人机验证;搜图/批量下载交给现成工具(见下面"C 级")。
4. **只取官方域名的资源**:inspect 出来的 `src` 先看域名是不是官方 CDN,再下载;非官方域的图一律不用(合规与版权)。

**关于旧 Bing 路线**:本技能**不自带**任何 Bing 爬虫(带了等于把已知失败路径装进来)。若环境里恰好装了 image-downloader,**仅当**题材是英文大众品牌/通用实景、且愿意逐张人工筛时可用;中文题材、冷门公司、中国语境一律走 B。**不要为取图临时自己写爬虫** —— 先用现成工具,取不到就降级纯排版。

**路径 D 的截图纪律**(负面事件题材,新闻/公告截图):

1. **来源分级**:交易所公告 / 监管文书 > 公司官方声明(含致歉信、澄清公告)> 媒体报道 —— **一线权威(新华社/央视/澎湃)与主流门户(腾讯新闻/新浪/网易/凤凰等)都是合格来源**,不必死守"最权威"的一家;真正排除的只有自媒体、聚合号、内容农场(无法核验、常带节奏)。
2. **截图必须保留可核验信息**:媒体名/机构名、标题、发布日期要截进画面 —— 把来源信息裁掉的截图不可用。Cookie 横幅、推荐流先关掉再截,只截正文区域。
3. **落盘与登记**:截图存 `assets/`,MANIFEST 一行登记"内容 / 来源 URL / 发布日期 / 许可(报道性合理引用)";入画用 `.img-frame.contain` + `.img-cap` 注明来源与日期(如"图:XX 新闻报道 · 2026-09")。
4. **负面财经题材同受 compliance.md 约束**:结尾免责行照加、口播不给操作建议、不预测价格;截图里出现的第三方 logo/人物沿用既有商标/肖像规则。
5. 截图命令(等懒加载后截正文区域;宿主内置浏览器的 screenshot 同理):

```bash
node -e "const {chromium}=require('playwright');(async()=>{
  const b=await chromium.launch(); const p=await b.newPage({viewport:{width:1280,height:900}});
  await p.goto(process.argv[1],{waitUntil:'domcontentloaded'});
  await p.waitForTimeout(2500);                                   // 等懒加载
  const art=(await p.$('article'))||(await p.$('main'))||await p.$('body');
  await art.screenshot({path:process.argv[2]});
  await b.close();})()" "https://媒体/报道页" assets/news-01.png
```

抽象信息(数字、对比、引用)**不需要图**:直接用版式本身(数字卡/大字/引语)做信息层,这是最省事也最高级的解法。

## 2. 搜图阶段的筛选(下载前,必走)

**query 设计**
- ✅ 加正向词:**全景 / 全貌 / 正面 / 远景 / 官方**
- ❌ 加排除词:**特写 / 近景 / 一角 / 半截**
- 搜人物加 `official portrait`;搜产品加 `press photo` / `official`

**缩略图先过一眼,四问:**
1. 主体在画面中央、显眼吗?(主体贴边 → 直接换)
2. 比例接近 16:9 吗?(目标比例优先,避免裁切)
3. 有水印 / 无关 logo / 别人脸吗?
4. 分辨率 ≥1200px 吗?(上屏会软的一律不要)

**一张不合适就继续搜下一张,不要凑合。**

## 3. 拿到图后的二次检查(必走)

```bash
node <技能>/scripts/prep-image.mjs --check assets/xxx.png
```

它会报:尺寸、比例、裁到 16:9 需要切掉多少、分辨率是否偏低、以及"主体若在边缘就先换图"的提醒。

**主体位置怎么判**:肉眼看缩略图 —— 主体在**上/中/下**哪一区?在边缘(y 接近 0 或 h)→ **放弃这张,重搜**;在中间但比例差 → 可以小裁,或直接用框的留白模式(见 §4)。

## 4. 优先用"框"解决,而不是裁图

`.img-frame`(tokens.css 内置)把**比例与裁切交给框,图片只管填**:

```html
<!-- 封面图: 按框比例裁切, --img-pos 决定保留哪部分主体 -->
<figure class="img-frame fx-grow" data-stage="2" style="--img-ratio:16/10; --img-pos:top">
  <img src="../assets/photo.png" alt="描述">
  <span class="img-tag">现场</span>
</figure>
<p class="img-cap">图注写在框外, 不写里面(框会裁掉)</p>

<!-- 截图/图表/带文字的图: 用 contain 不裁切, 居中留白 -->
<figure class="img-frame contain" style="--img-ratio:16/9">
  <img src="../assets/shot.png" alt="截图">
</figure>
```

- **硬规则:图片必须套框,禁止裸放 `<img>`**。裸图会按自身比例撑破版式。
- `--img-ratio` 想要什么要什么(16/10 稳重、1/1 方图、16/9 宽屏),**不必强求 16:9**。
- `--img-pos: top|center|bottom` = 用 object-position 控制主体可见区 —— 这是**替代硬裁的首选手段**。
- 截图/图表/带文字信息的图**必须** `.contain`:裁切会丢信息。
- `.img-scrim` 底部压暗,让白字压在照片上仍可读;`.img-cap` 图注、`.img-tag` 角标。

## 5. 裁切(最后手段,有硬限制)

搜索 5 张都不满意时,按顺序考虑:①**换题材**(改用数字卡/大字/引言);②**换版式**(contain 留白也是高级感);③**找官方授权图**;④才轮到裁切。

```bash
node <技能>/scripts/prep-image.mjs --crop assets/in.png assets/out.png --ratio 16:9 --anchor bottom
```

**裁切硬限制**(脚本会强制):目标比例不能需要放大补边;裁掉面积 **≤20%**,超了直接拒绝并提示改用 `contain`。

裁完**必须**肉眼看一眼主体是否完整 —— 宁可改用 `--img-pos`,也不要裁到主体。

## 6. 视觉验证三件套(改完 HTML 必走)

1. **重新截图**:`node <技能>/scripts/capture.mjs <项目> --mode still`,看 `preview/<id>.png`
2. **核对主体位置**:主体在画面中央偏上吗?有没有被裁掉一半?
3. **抽成片实际帧**:`ffmpeg -ss <时刻> -i out/final.mp4 -frames:v 1 frame.png` —— **必须核对成片的帧**,不要只看截图管线的产物(截图与成片的淡入淡出、字幕时机可能不同)

## 7. 合规与登记(与 authoring.md 一致)

- 每个素材落盘 `assets/`,在 `assets/MANIFEST.md` 登记:文件名 / 内容 / 来源 URL 或渠道 / 许可
- 无水印(有则换图;裁水印要确认裁掉面积 ≤20% 且主体完整)
- 商标/logo 只在"谈论该品牌"的语境使用,不做装饰滥用
- 照片须来自可授权来源;查不到授权的人物照宁可改用纯文字引语卡
- 截图注明出处(官方文档名 + 日期)
- **禁止凭空生成 logo、截图、头像、二维码**
- 素材必须先落本地再写进 HTML(capture 只等 4s,外链图加载不动会被跳过)

## 8. 常见题材的取图建议

| 题材 | 首选路径 | 备注 |
|---|---|---|
| 中国 AI 公司 / 港股 IPO | B(官网 DOM) | Bing 系统性失败;官网 hero/产品页资源最全 |
| 国外科技公司 | A(官方 brand kit)+ B | simple-icons 直接 curl logo |
| 高校 / 校园 | B(学校官网、"官微"图) | 实景图要求"正面/全貌",主体易贴边 |
| 历史人物 / 老照片 | C(Wikipedia CC) | 注意版权年限 |
| 暴雷 / 监管处罚 / 诉讼 / 翻车争议 | D(公告与报道截图) | 官网无此类素材;截主流媒体报道或公告页,保留媒体名与日期;财经负面同受 compliance.md 约束 |
| 财报数据 / 对比 | 不用图 | 数字卡 + 表格版式 |
| 抽象概念(增长/连接/未来) | 不用图 | 渐变 + 大字 + 图标 |
