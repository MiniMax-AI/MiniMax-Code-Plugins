# case-verify：案例引用核验

## 目的

编造或错引案例是法律写作中的高危错误：案号格式似真而实假、案例存在但
被后续判决推翻、引用的是顺带意见而非裁判要旨——这些在提交法院或客户前
都必须拦住（G10）。

本技能的核验强度按数据源分档：配置了商业案例库就做实质核验；未配置就
诚实降级为格式校验 + 人工核查路径，**绝不凭模型记忆确认一个案号**。

## 前置检查

1. 读取 docs/guardrails.md 执业画像，确认无 `[填空]`；有则停止并引导先跑
   `cold-start-interview`；
2. 查画像数据源配置：北大法宝 / 聚法是否已配置，决定本技能走实质核验
   还是降级模式；
3. 查 `verification-log.md`：同一案号 90 天内已核验的可复用，注明复用日期；
   但案例核验的复用要更谨慎——案例的"后续发展"（再审、改判、被指导性
   案例替代）不会主动推送，重要用途建议重验。

## 操作规程

### 1. 案号格式校验

中国大陆案号基本形态（2016 年起统一样式 [模型知识—待核实，细节以最高法院
案号管理规定为准]）：

```
（收案年份）+ 法院代字 + 案件类型字 + 编号 + 号
例：（2021）最高法民申1234号
     ↑          ↑      ↑     ↑
   年份      法院代字 类型字  编号
```

校验要点：

- 年份为四位数外加全角圆括号（ ），不是方括号、不是半角括号；
- 法院代字：最高法院为"最高法"，地方法院为行政区划简称加"法"字（如
  "京""沪01"等样式 [模型知识—待核实]）；
- 类型字：民初/民终/民申/民再/刑初/刑终/行初/执 等；
- 编号为数字。

格式不符合的，**先提示格式疑点再决定是否继续**——格式错误本身就是引用
可疑的信号，但不等于案例不存在（可能是转写错误）。

指导性案例、公报案例有其自编号（如"指导案例24号"），与案号是两套体系，
分别核验。

格式正误对照示例：

| 输入 | 校验结论 |
| --- | --- |
| （2021）最高法民申1234号 | 格式符合规范 |
| [2021]最高法民申1234号 | 括号错误（应为全角圆括号），提示转写疑点 |
| (2021）最高法民申1234号 | 半角/全角括号混用，提示转写疑点 |
| （2021）北京一中民初12号 | 法院代字形态可疑（通常不含"法院"全称），提示核对 |
| 指导案例24号 | 非案号，改按指导性案例体系核验 |

### 2. 实质核验（已配置北大法宝/聚法时）

1. 按案号精确检索；
2. 命中后核对元数据：法院名称、案由、裁判日期、审级、当事人（与使用者
   描述是否一致）；
3. 记录文书来源标签：`[北大法宝]` 或 `[聚法]`；
4. 检索该案例的后续状态线索（是否被再审、改判），数据库有相关标注的一并
   记录；数据库未标注的，在输出中说明"后续状态未核查" [需复核]。

### 3. 降级模式（未配置商业源时）

1. 只做第 1 步格式校验；
2. 案例存在性与内容一律标 `[模型知识—待核实]`，措辞示例：
   "案号格式符合规范，但本会话无案例库可用，案例存在性与内容未经核验
   [模型知识—待核实]"；
3. 给出人工核查路径：
   - 裁判文书网（wenshu.court.gov.cn）官网人工检索；
   - 人民法院案例库官网；
   - 配置北大法宝/聚法后重跑本技能；
4. **不得**因为"模型记得这个案例"而给出 verified 类判定。

### 4. 引用性质检查提醒

核验通过不等于引用得当。输出中必须提醒使用者确认：

- 引用的是**裁判要旨 / holding**（判决理由中对法律适用有决定意义的判断），
  而不是**顺带意见 / obiter**（与判决结果无决定关系的附带论述）；
- 引用内容与拟证明的命题是否真正对应——案例支持的是 A 命题，不能拿来
  支持相近但不同的 B 命题；
- 指导性案例具有"应当参照"的效力定位 [模型知识—待核实]，普通案例是
  说服性参考，产物中措辞应有区分。

### 5. 写入 verification-log.md

```markdown
| 日期 | 案例引用 | 判定 | 证据来源 | 复核截止 |
| --- | --- | --- | --- | --- |
| 2026-08-18 | （2021）最高法民申1234号 | verified（北大法宝命中，后续状态未核查） | [北大法宝] | 2026-11-16 |
```

降级模式的记录判定写 "format_only（未实质核验）"。

## 输出模板

```markdown
## 案例核验表
| 案例引用 | 格式校验 | 核验判定 | 法院/日期 | 证据来源 | 建议 |
| --- | --- | --- | --- | --- | --- |
| （2021）最高法民申1234号 | 通过 | verified / format_only / not_found | {法院，裁判日期} | [北大法宝] / — | {引用建议} |

## 引用性质提醒
- [ ] 确认引用的是裁判要旨而非顺带意见
- [ ] 确认案例支持的命题与引用处命题一致
- [ ] 指导性案例与普通案例的措辞已区分
- [ ] 后续状态（再审/改判）已核查或已声明未核查

## 降级声明（未配置商业源时）
本会话无案例库可用，以上为格式校验结果，案例存在性与内容
[模型知识—待核实]，人工核查路径：{裁判文书网 / 人民法院案例库 / 配置商业源}。
```

## 本技能不做什么

- 不凭模型记忆确认任何案号或案例内容；
- 不爬裁判文书网（无公开 API、反爬严格，见 legal-research 的 politeness
  条款）；未配置商业源时只给人工核查路径；
- 不做法条的时效核验（那是 statute-verify）；
- 不评价案例"用得妙不妙"的诉讼策略问题；
- 不把 format_only 降级结果表述成实质核验结论。

## 收尾与下一步

- 核验记录写入 verification-log.md，回填调用方的 `[CITE:__]` 占位；
- 提醒：产物发出前仍需过 `citation-audit`；
- not_found 的案号，建议使用者核对原始出处（对方文书、旧 memo），排查
  转写错误；
- 发现拟引用案例可能已被后续裁判推翻的迹象时，按 G2 第三项
  flag-but-don't-use 处理并显式提示。
