# 风险条款速查库

## 目的

为各专项审查技能提供**统一的条款级检查口径**：每类条款长什么样算有风险、
审查时盯哪几个点、相关法条去哪里核、市场惯例的大致区间在哪里。本库只提供
「检查框架」，不提供结论——结论由调用方结合画像 playbook 立场作出。

两条使用纪律：

1. **法条一律占位或待核验**（G10）：本库中法条引用以 [CITE:__] 占位或标
   [模型知识—待核实]；调用方成稿前必须经 legal-core 的 `statute-verify`
   核验，未核验保持占位，严禁凭记忆填入条文号。
2. **惯例区间只是参照**：「市场惯例区间」均为 [模型知识—待核实]，用于发现
   「明显离谱」的条款，不得作为谈判依据写进对外文件（G1：它不是工具来源）。

条文要点的集中地图见 `references/civil-code-contract-map.md`（该文件全部
内容使用前必须经 statute-verify 核验）。

## 前置检查

- 调用方已完成立场判定（买方/卖方、披露方/接收方等）；本库每个「审查要点」
  都按立场分述，立场未定不得使用本库下结论。
- 调用方已加载画像 playbook；本库的「市场惯例区间」不能替代 playbook 立场。
- 命中画像红线条款的，调用方按画像红线纪律处理（出现即提示，严重度下限
  🟠，见 G9 与画像「红线条款与审批底线」节）。

## 操作规程（调用方式）

1. 调用方传入：合同类型、本方立场、需要检查的条款类别清单。
2. 按下表逐类取出「常见风险形态 + 审查要点」，逐条与合同文本比对。
3. 命中的风险形态 → 交给调用方按 playbook 分桶；本库不直接给 🟢🟡🔴。
4. 涉及法条的，在调用方 memo 中保持 [CITE:__] 占位或 [模型知识—待核实]
   标注，统一在收尾时过 `statute-verify` 与 `citation-audit`。
5. 命中画像红线条款的项，调用方按「出现即提示、严重度下限 🟠」处理
   （G9 与画像「红线条款与审批底线」节）；本库在各类下不重复此标注。

## 条款类型速查（九类）

### 1. 定义与标的

- **常见风险形态**：标的描述不特定（无型号/规格/编号）；「等相关产品」
  「等服务」开口表述；定义条款与正文用语不一致；附件清单与正文标的不符。
- **审查要点**：标的是否可唯一识别；开口表述能否收口（如「以双方书面确认
  的订单为准」）；定义是否全文一致。
- **相关法条**：合同一般条款 [CITE:__]。
- **市场惯例区间**：[模型知识—待核实] 技术参数、清单通常附件化，并约定
  附件与正文的效力顺位。

### 2. 质量

- **常见风险形态**：主观标准（「符合甲方要求」「达到行业领先水平」）；标准
  版本不锁定；多重标准冲突未约定顺位；质量保证被写成无限期无限范围。
- **审查要点**：标准是否客观可检验；国标/行标/企标/样品的顺位；质保期
  起算点与范围；质量异议期与检验程序的衔接（民法典第六百二十条、第六百
  二十一条相关 [模型知识—待核实]）。
- **相关法条**：[CITE:__]。
- **市场惯例区间**：[模型知识—待核实] 货物买卖常见约定明确异议期；异议期
  长短因行业与标的不同差异大，以画像 playbook 为准。

### 3. 交付

- **常见风险形态**：交付地点不明（风险节点随之不明）；「代办托运」下货交
  承运人的风险归属未写明；分批交付的违约认定缺失；安装调试与交付验收的
  关系不清。
- **审查要点**：交付地点→风险移转节点的对应关系（交付主义
  [模型知识—待核实]，民法典第六百零四条相关）；运输与保险承担；迟延交付
  的违约责任是否与支付条款对称。
- **相关法条**：[CITE:__]。
- **市场惯例区间**：[模型知识—待核实] 设备类合同常把风险节点与「验收合格」
  挂钩，买卖双方博弈点即在于此。

### 4. 支付

- **常见风险形态**：节点单一且后置（买方视角有利、卖方视角高危）或单一且
  前置（反之）；发票与付款的先后不明；逾期利息/违约金缺失或畸高畸低；
  质保金比例与返还条件不明。
- **审查要点**：节点结构（预付/发货/到票/验收/质保金）对照 playbook；
  发票类型与时点；逾期责任是否对等；币种、税率变化分担（涉外时触发 B5
  升级并按 G3 处理）。
- **相关法条**：[CITE:__]。
- **市场惯例区间**：[模型知识—待核实] 多节点分期是常态；各节点比例因行业
  而异，以画像 playbook 为准。

### 5. 违约

- **常见风险形态**：违约责任只写一方；违约金畸高（存在被司法调整的空间
  [模型知识—待核实]）或畸低形同虚设；赔偿范围含不含间接损失/可得利益未
  写明；单方赔偿上限不对等。
- **审查要点**：对照民法典违约责任条款 [CITE:__]（继续履行、补救措施、
  赔偿损失）；违约金与实际损失的关系；上限结构（固定额/合同总额比例/
  实际损失孰低）是否对等。
- **相关法条**：违约责任与违约金调整规则 [CITE:__]。
- **市场惯例区间**：[模型知识—待核实] 以画像 playbook 的赔偿上限立场为准；
  画像红线如载明「不接受无上限赔偿」，命中即提示（严重度下限 🟠）。

### 6. 解除

- **常见风险形态**：约定解除权单方倾斜；触发条件模糊（「重大违约」无定义）；
  解除后果缺失（已履行部分如何结算、资料设备如何返还）；继续性合同无退出
  机制。
- **审查要点**：法定解除之外的约定解除是否平衡；解除程序（通知形式、
  宽限期）；解除后果条款是否完整；与违约条款的衔接。
- **相关法条**：[CITE:__]。
- **市场惯例区间**：[模型知识—待核实] 框架合同常见「提前 N 日书面通知可
  终止」的安排，N 的长短以 playbook 为准。

### 7. 保密

- **常见风险形态**：定义过宽吞噬公共知识；例外情形缺失；期限无限长；返还
  销毁无程序；保密外衣下夹带竞业/排他/不招揽（见 nda-review 的
  Scope check）。
- **审查要点**：定义范围、例外齐备性、期限与起算、返还销毁程序、违约责任
  上限、是否隐含知识产权许可。
- **相关法条**：[CITE:__]（另注意先合同保密义务 [模型知识—待核实]）。
- **市场惯例区间**：[模型知识—待核实] 期限长短以画像 NDA 立场为准。

### 8. 知识产权

- **常见风险形态**：背景 IP 与前景 IP 不分；「为履约产生的成果归甲方」
  一刀切；改进成果归属不明；隐含许可（评估目的的使用被写成可延展授权）；
  标识使用无限制。
- **审查要点**：归属规则（背景/前景/改进分别约定）；许可范围、期限、可否
  转许可；与保密条款的衔接；归属复杂（合作开发、委托开发）时触发 B5 升级。
- **相关法条**：[CITE:__]（技术合同相关规则 [模型知识—待核实]）。
- **市场惯例区间**：[模型知识—待核实] 委托开发成果归属约定优先；无约定时
  的法定规则须核验后引用。

### 9. 争议解决

- **常见风险形态**：法院与仲裁混写（「由 XX 法院仲裁」之类表述）；约定境外
  管辖/仲裁（B5 升级）；管辖约定与主从合同不一致；或裁或诉安排的效力问题
  [模型知识—待核实]。
- **审查要点**：争议解决方式二选一且表述明确；地点对照画像首选管辖；主合同
  与附件、订单的一致性；涉外因素的准据法（按 G3 法域识别五步处理）。
- **相关法条**：[CITE:__]。
- **市场惯例区间**：[模型知识—待核实] 商事合同常见原告所在地/被告所在地/
  合同履行地/签约地的博弈，以画像首选管辖为准。

## 使用示例（调用流程示范）

场景：sales-contract-review 审一份设备采购合同，买方立场。

1. 调用方传入：合同类型=买卖合同；立场=买方；类别清单=质量、交付、支付、
   违约、解除、争议解决（验收并入交付类检查）。
2. 本库返回第 2、3、4、5、6、9 类的风险形态与审查要点。
3. 调用方比对文本后命中：「质量」类命中「主观标准（符合甲方要求）」；
   「支付」类命中「节点单一且后置（验收后 180 天一次性付款）」。
4. 调用方按画像 playbook 分桶：主观质量标准 → 🟡（可改）；180 天账期
   超出 playbook 账期立场 → 🟡（超出 playbook）。拟引用条文保持
   [CITE:__]。
5. 收尾：memo 引用统一过 `statute-verify` 与 `citation-audit`。

反例：调用方跳过立场判定直接套本库——同一「180 天账期」对买方有利、
对卖方高危，没有立场就无法判断它是不是风险形态。立场未定的调用一律
打回。

## 输出模板

本库不直接产出面向用户的文件；调用方引用时按下述内部格式传递检查结果：

```text
[条款类别] <九类之一>
- 命中风险形态：<逐条>
- 审查要点核对结果：<通过 / 存疑；存疑写明哪一点>
- 拟引用法条：[CITE:__]（待 statute-verify）
- 备注：<超出 playbook 或命中画像红线的项在此标注>
```

## 本技能不做什么

- 不下审查结论（不直接给 🟢🟡🔴）——分桶是调用方结合 playbook 的职责。
- 不提供硬编码阈值；「市场惯例区间」仅供发现明显离谱条款，不进对外文件。
- 不直接引用法条成稿——一律 [CITE:__] 占位或 [模型知识—待核实]，成稿前
  经 statute-verify（G10）。
- 不覆盖九类之外的行业专门条款（如金融、建工、医药监管条款）；遇到时提示
  走通用规程并建议律师介入。

## 收尾与下一步

- 调用方用完本库后，memo 中的法条引用统一过 `citation-audit`（G10）。
- 发现本库未覆盖的条款类型或新风险形态时，在 memo 的 FYI 区记录，供后续
  版本补库；不在本次审查中临时造标准。

## 确定性高条号声明

民法典第四百七十条（合同一般条款）、第五百七十七条（违约责任）为确定性
高条号，但本库「相关法条」与调用方 memo 中的正式引用一律先以 [CITE:__]
占位，经 legal-core `statute-verify` 核验现行文本后填入（G10）。
