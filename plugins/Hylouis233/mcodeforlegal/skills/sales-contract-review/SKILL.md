# 买卖合同专项审查

## 目的

按本方立场（买方/卖方）把一份买卖合同逐项过堂，对照民法典合同编买卖合同
章的基本框架与画像 playbook 立场，把条款分成 🟢🟡🔴 三桶，产出可行动的
triage memo。

与 nda-review 同构：结论依附立场、🟢 不出自默认值、产物去向先检查、红线
命中即停止。本技能的检查清单调用 `risk-clause-database` 取得各类条款的
风险形态与审查要点，不另起一套口径。

本技能遵守 legal-core Shared guardrails（G1–G12）与docs/scenes/contract-review-cn.md；
冲突时以 legal-core 为准。

## 前置检查

1. 已由 `contract-review` 路由器完成画像检查与路由确认；未经路由器直接进来的先
   补齐。
2. 文本完整可读；主协议 + 订单 + 附件结构的，确认各份是否齐全，缺件在
   reviewer note 的「已读」行写明。
3. 用户角色已识别，决定 G4 标头档位与 G5 后果门口径。
4. 金额初判：合同金额是否超过画像的合同审批金额阈值——超过即触发 B5
   升级，memo 照出但明示「须升级人工」。

## 操作规程

### 第 0 步：Matter context 与 Destination check

- Matter context：查 `matters/_log.yaml`；已有相关事项则挂入（memo 存
  drafts/，notes.md 追加进展）；长期供货关系或框架协议的，建议经
  `matter-workspace` 建档（提示即可，不强制）。
- Destination check：产物去向在保密圈外的 flag 并可提供内外双版本；memo
  含本方价格底线、账期立场等信息，外泄直接损害谈判地位。去向不明按仅
  内部处理。

### 第 1 步：立场判定（买方 / 卖方）

- **买方视角**重点：质量标准是否可检验可举证、检验期间是否够用、交付与
  风险转移节点是否靠后、付款节点是否与验收挂钩、逾期利息与违约金是否
  对等、解除权是否顺手。
- **卖方视角**重点：质量标准是否被写成无限保证、检验期间是否过长或被
  「异议期不限」架空、风险转移节点是否靠前、付款节点是否前置有保障、
  所有权保留是否写明、买方解除权是否被无限扩大。
- 双方立场都要检查「义务对等性」：对方的违约责任轻、本方重，本身就是
  标记项。
- 文本角色与业务实质不一致的（如名为购销实为代销/代理），以业务实质为准，
  在 memo 中说明，并评估是否需向用户提出类型重路由。

### 第 2 步：加载 playbook（买卖立场）

- 读取画像中的买卖合同立场节；经律师审定的直接使用，默认模板的最高只能
  🟡。
- 未填的，现场询问关键立场并**经 `customize` 技能写回画像**（标
  [已确认—日期]、「未经律师审定」）：可接受的账期结构、是否接受所有权
  保留安排（卖方视角）或要求对方提供（买方视角）、质量异议期的惯例区间、
  管辖偏好。
- 用户答不出：不编造，相关项整体 🟡，理由「立场未确认」。

### 第 3 步：分类检查清单（八类，调用 risk-clause-database）

逐类检查。**不设硬编码阈值**，期限、比例、金额的判断一律比对画像/playbook
立场；立场未覆盖的标 🟡 写「超出 playbook」。条文引用纪律：民法典第五百
七十七条、第六百四十一条为确定性高条号，但对外产物中的正式引用一律先以
[CITE:__] 占位，经 legal-core `statute-verify` 核验现行文本后填入（G10）：

1. **标的物与质量条款**：标的描述是否特定化（型号、规格、技术参数附件化）；
   质量标准的明确性——国标/行标/企标/样品，版本是否锁定，「符合甲方要求」
   之类主观标准是高危项；检验期间与质量异议期的约定（民法典第六百二十条、
   第六百二十一条相关 [模型知识—待核实，引用前经 statute-verify 核验]）——
   买方视角关注期间是否过短以致丧失异议权，卖方视角关注期间是否被写成
   不限期。
2. **交付与风险转移**：交付地点、方式、运输承担；交付地点决定风险移转节点
   （民法典第六百零四条采交付主义 [模型知识—待核实，引用前经
   statute-verify 核验]）；在途货物、代办托运、需要安装调试的设备，风险
   节点是否与「验收合格」脱钩——买方尽量让风险晚移，卖方反之。
3. **价款与支付**：价格是否含税、税率变化的分担；支付节点（预付/发货/
   到票/验收/质保金）与比例结构对照 playbook；发票开具时点与类型（专票/
   普票）约定；逾期付款利息或违约金的标准——过高或过低都标记，畸高部分
   存在被司法调整的空间 [模型知识—待核实]。
4. **验收条款**：验收标准、期限、程序；「逾期未提出异议视为验收合格」的
   默示验收条款——买方视角争取删除或延长，卖方视角争取写上；验收与安装
   调试、试运行的衔接是否清楚。
5. **违约责任**：对照民法典第五百七十七条 [CITE:__]（继续履行、采取补救
   措施、赔偿损失等）；违约金与损害赔偿的关系约定；是否设了单方赔偿上限、
   上限是否对等；间接损失/可得利益的排除或纳入——买卖双方立场相反，
   按第 1 步立场检查。
6. **所有权保留**：民法典第六百四十一条 [CITE:__] 允许约定买受人未履行
   付款等义务时标的物所有权属于出卖人；卖方视角——有无此条款、是否考虑
   登记对抗问题（保留的所有权未经登记不得对抗善意第三人
   [模型知识—待核实，引用前经 statute-verify 核验]）；买方视角——保留
   条款与已付款比例、取回权行使条件是否失衡。
7. **解除条款**：法定解除情形之外有无约定解除权；解除权的触发条件是否
   清晰、是否单方倾斜；解除后果（退货、退款、已交付部分结算、违约责任
   存续）是否写全；继续性供货关系的任意解除或提前通知终止安排。
8. **管辖与争议解决**：法院或仲裁、地点，对照画像首选管辖；约定境外管辖/
   仲裁的触发 B5 升级（并按 G3 处理法域问题）；争议解决条款与订单、附件
   是否一致。

红线扫描：全量对照docs/scenes/contract-review-cn.md A8.1 的 blocks 与画像红线。买卖合同场景
的高发区：阴阳合同（两套价格文本）、无资质经营特许商品（如危化品、医疗
器械、食品的许可）、借买卖外观走规避监管的安排。命中即停止并明示。

### 第 4 步：分桶 🟢🟡🔴

- 🟢：八类全部落在经律师审定的 playbook 立场内；默认模板立场最高 🟡。
- 🟡：偏离 playbook 但可修；playbook 未覆盖；文本歧义。
- 🔴：命中 blocks 红线或画像审批底线；或条款组合构成重大不利且不可经修改
  补救（如买方视角下「款到发货 + 风险出厂即转移 + 异议期三天 + 卖方责任
  上限为货款一成」的组合）。
- 双轴标注：每项同时按 G9 给法律风险轴（🔴🟠🟡🟢）与商业摩擦轴（阻碍/
  拖慢/费解/无感）。

### 第 5 步：输出 memo

使用与 nda-review 统一的 triage memo 模板（见下方）。执行摘要只放机械性
一行修改；需起草新语言的（重写质量条款、补验收程序）只写「建议转法务
起草」。

### 第 6 步：后果门与收尾

- 🔴：明示「不提交签署流程、不向相对方承诺」，按 G5 生成「带给律师的一页
  brief」，非律师用户停止。
- 🟢 且非律师用户：进入签署流程前按 G5 显式确认知悉后果并获得明确指令，
  同时生成律师 brief。
- 🟡：逐条建议，改完复审。
- 含质保期、框架合作期限、自动续期条款的：调用 `renewal-tracker` 登记。
- 全部条文引用过 `citation-audit`（G10），FAIL 不得外发。

## 本技能不做什么

- 不代拟条款或修改稿语言——需起草的一律「建议转法务起草」。
- 不凭默认值给 🟢（playbook 未经律师审定时天花板 🟡）。
- 不设硬编码阈值（账期几天算长、违约金百分之几算高），一律比对画像/
  playbook。
- 不替用户做交易决策（要不要买/卖、价格谈多少），只标风险与摩擦。
- 不在缺件（缺订单、缺附件、缺技术协议）时假装审完了——已读范围如实
  写明。
- 不处理 🔴 事项的后续（生成律师 brief 后停止，不出绕行方案）。
- 对非律师用户不出具法律意见（G5 UPL 门控）。
- 不直接手改画像：现场取得的立场经 `customize` 写回。

## 收尾与下一步

1. 按后果门分流：🔴 停止转律师；🟡 修订后复审；🟢 显式确认 + 律师 brief。
2. 含质保期/合作期限/自动续期 → `renewal-tracker` 登记
   contracts/renewal-register.yaml。
3. 引用过 `citation-audit`，条文原文经 `statute-verify` 核验。
4. 需要业务方版本 → `contract-summary`（上游严重度只作下限，G9）。
5. 框架合作进入长期履行的，提示经 `matter-workspace` 建档，后续订单审查
   挂同一事项 slug。
