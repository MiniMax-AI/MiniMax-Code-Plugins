# 租赁合同专项审查

## 目的

把一份租赁合同从「看租金贵不贵」变成「按本方立场逐项过堂」：确认审查
视角（出租方/承租方），用经确认的 playbook 立场逐项比对，把结果分成
🟢🟡🔴 三桶，产出一份可直接行动（改、谈、签、停）的 triage memo。

本技能的核心纪律有三条：

1. **结论依附立场**：同一条转租限制对出租方是管控手段、对承租方是
   经营灵活性约束，不先定立场就无权下结论；
2. **🟢 不出自默认值**：🟢 只能基于律师审定的 playbook 立场；画像里
   还是默认模板时，单份合同最高 🟡（docs/scenes/contract-review-cn.md B3）；
3. **藏条款必现形**：名为租赁实为买卖（以租代购）、融资租赁、承包
   经营的，一律 auto-🟡 并明示，不套租赁清单蒙混。

本技能遵守 legal-core Shared guardrails（G1–G12）与docs/scenes/contract-review-cn.md；冲突时以 legal-core 为准。

## 前置检查

1. 已由 `contract-review` 路由器完成画像检查与路由确认；未经路由器直接进来
   的先补齐。
2. 文本完整可读；产权证复印件、平面图、交接清单、装修方案等附件不
   齐的，在 reviewer note 的「已读」行如实写明。
3. 用户角色已识别，决定 G4 标头档位与 G5 后果门口径。
4. 金额初判：租期总租金是否超过画像的合同审批金额阈值——超过即触发
   B5 升级，memo 照出但明示「须升级人工」。

## 操作规程

### 第 0 步：Matter context 与 Destination check

- Matter context：查 `matters/_log.yaml`；已有相关事项则挂入（memo
  存 drafts/，notes.md 追加进展）；长期租赁关系（多年期、含续租安排）
  的，建议经 `matter-workspace` 建档（提示即可，不强制）。
- Destination check：产物去向在保密圈外的 flag 并可提供内外双版本；
  memo 含本方租金底线、免租期立场等信息，外泄直接损害谈判地位。去向
  不明按仅内部处理。

### 第 1 步：立场判定（出租方 / 承租方）

- **出租方视角**重点：租金支付保障（押金、预付、担保）；用途限制与
  违法使用风险；转租管控；租赁物返还状态与装修添附的处理；承租人
  拖欠租金时的解除与清场路径。
- **承租方视角**重点：租赁物权属与出租权限（是否有权出租、有无抵押、
  查封）；租赁期限与续租确定性；免租期与装修期安排；维修义务分配；
  买卖不破租赁与优先购买权的保护；出租方单方解除权是否过宽。
- 两个视角都查「义务对等性」：逾期付款责任与逾期交房/维修不力责任
  是否对称。
- 文本角色与业务实质不一致的（如名为租赁实为承包经营、场地合作），
  以业务实质为准，在 memo 中说明，并评估是否需向用户提出类型重路由。

### 第 2 步：加载 playbook（租赁立场）

- 读取画像中的租赁合同立场节；经律师审定的直接使用，默认模板的最高
  只能 🟡。
- 未填的，现场询问关键立场并**经 `customize` 技能写回画像**（标
  [已确认—日期]、「未经律师审定」）：
  1. 可接受的租期区间与续租安排偏好（具体数字由用户给出，本技能不
     提供硬编码阈值）；
  2. 租金支付节奏与押金比例的立场；
  3. 免租期/装修期的惯例区间；
  4. 转租的态度（出租方视角：禁止/经同意；承租方视角：是否要求保留
     转租或分租权利）；
  5. 管辖偏好（与 B9 首选管辖对齐）。
- 用户答不出：不编造，相关项整体 🟡，理由「立场未确认」。

### 第 3 步：Scope check（藏条款检查，无条件执行）

通读全文，识别协议是否在租赁外衣下夹带其他法律关系。命中以下任一
情形，**无条件 auto-🟡**，并在执行摘要第一行明示「本合同名为租赁
合同，实际含有 XX 安排」：

1. **以租代购**：约定租期届满租赁物归承租方、租金总额接近或等于
   价款——实为分期付款买卖，按买卖逻辑另列标记项。
2. **融资租赁**：出租方按承租方选择购买租赁物出租——融资租赁有
   专门规则 [模型知识—待核实，引用前经 statute-verify 核验]，本
   清单不覆盖，提示重路由或律师介入。
3. **承包经营/场地合作**：租金与经营流水挂钩、出租方参与经营管理
   ——实为承包或合作安排。
4. **居住房屋群租/分割出租**：违反居住房屋租赁管理规定的迹象
   [模型知识—待核实]，涉行政合规风险。
5. **违法建筑或无权出租**：租赁物系违建、或出租方明显无出租权限
   （无权属证明、转租链条断裂）——合同效力风险，评估是否升级 🔴。

处理方式：藏条款部分按真实法律关系另列标记项（起点 🟡）；命中画像
红线条款的按画像红线纪律（出现即提示，严重度下限 🟠，G9）。

### 第 4 步：分类检查清单（八类，调用 risk-clause-database）

逐类检查。**不设硬编码数值阈值**——租期长短、押金比例、免租期长短
一律比对画像/playbook 立场；立场未覆盖的标 🟡 写「超出 playbook」。
通用条款风险形态调用 `risk-clause-database` 取统一口径，本节只列
租赁专项要点：

1. **租赁物与用途**：租赁物的特定化（坐落、面积、权属证号、附图）；
   出租方权属与出租权限核查（产权证、委托书、转租同意文件）；用途
   约定与实际经营需求是否匹配；用途违法或违反管理规约时的责任分配。
2. **租赁期限**：起止日期与交付日期的衔接；**租赁期限不得超过二十年，
   超过部分无效**（民法典第七百零五条 [CITE:__]）；租期较长未采用
   书面形式或期限约定不明时按不定期租赁处理的风险 [模型知识—待核实，
   引用前经 statute-verify 核验]；续租条款与承租方的优先承租权
   [模型知识—待核实]。
3. **租金与押金**：租金数额、支付节奏、递增机制（固定递增/挂钩指数）
   是否写明；发票开具；押金数额、性质（担保范围是否覆盖损坏赔偿与
   欠费）、返还条件与返还时限；押金扣减的举证与结算程序；逾期支付
   的违约责任与出租方的处理权限。
4. **维修义务分配**：法定默认出租方承担维修义务、当事人可另行约定
   [模型知识—待核实，引用前经 statute-verify 核验]——合同把全部
   维修推给哪一方、与法定默认是否一致；日常维修与大修/主体结构维修
   的划分；维修期间租金减免与承租人自行维修后的费用扣抵安排
   [模型知识—待核实]。
5. **转租限制**：是否禁止转租、是否约定经同意可转租；未经同意转租
   的解除后果 [模型知识—待核实，引用前经 statute-verify 核验]；
   承租方视角关注「同意不得无故拒绝/拖延」的写法与默示同意规则
   [模型知识—待核实]；次承租人的权利保护 [模型知识—待核实]。
6. **买卖不破租赁与优先购买权**：租赁物在租赁期间所有权变动的，
   租赁关系不受影响（民法典第七百二十五条 [CITE:__]）——承租方
   视角核查有无「出租方可随时转让且租赁关系终止」之类试图架空该
   规则的表述；出租方出卖租赁**房屋**时承租人的优先购买权及其例外、
   通知义务与妨害救济 [模型知识—待核实，引用前经 statute-verify
   核验]；租赁物已抵押或被查封的，承租方占用稳定性风险单列标记项。
7. **装修添附处理**：装修方案是否需出租方批准；装修期/免租期安排；
   租赁期满或提前解除时装修添附的处理——拆除复原、折价归出租方、
   无偿归出租方的不同约定对双方利益影响重大（具体规则
   [模型知识—待核实，引用前经 statute-verify 核验]）；附属设备
   归属清单是否附件化。
8. **解除事由与争议解决**：法定解除情形之外的约定解除权是否平衡
   ——承租方拖欠租金经催告仍不付的解除 [模型知识—待核实]、租赁物
   危及安全健康时的随时解除 [模型知识—待核实]、非因承租方原因
   致使无法使用时的解除 [模型知识—待核实]；提前退租/提前收房的
   通知期与违约金是否对等；解除后果（腾退、交接、欠费结算、装修
   处理）是否写全；管辖对照画像首选管辖。

红线扫描：全量对照docs/scenes/contract-review-cn.md A8.1 的 blocks 与画像红线。租赁
场景的高发区：阴阳租金文本（避税目的）、违建出租、借租赁外观规避
行业准入监管。命中即停止并明示。

### 第 5 步：分桶 🟢🟡🔴

- **🟢 可推进**：八类全部落在经律师审定的 playbook 立场内；默认
  模板立场最高 🟡。
- **🟡 需修订或需人判断**：偏离 playbook 但可修；playbook 未覆盖；
  命中 Scope check 藏条款；权属或出租权限待核验。
- **🔴 不得推进**：命中 blocks 红线或画像审批底线；或条款组合构成
  重大不利且不可经修改补救（如承租方视角下「租期超长 + 出租方可
  任意解除 + 装修无偿归出租方 + 押金返还无时限」的组合）。
- **双轴标注**：每项同时按 G9 给法律风险轴（🔴🟠🟡🟢）与商业摩擦轴
  （阻碍/拖慢/费解/无感）。分桶时先看组合、再看单项。

### 第 6 步：输出 memo

使用统一 triage memo 模板（见下方）。执行摘要只放机械性一行修改；
凡是需要起草新语言的（重写维修分配条款、补装修添附处理条款），建议
栏只写「**建议转法务起草**」，不在 memo 里代拟。

### 第 7 步：后果门与收尾

- 结论含 🔴：memo 首页明示「**本合同不提交签署流程、不向相对方作出
  任何承诺**」，按 G5 生成「带给律师的一页 brief」，非律师用户到此
  停止。
- 结论 🟢 且用户为非律师：进入签署流程前按 G5 动作闸门——显式确认
  知悉后果并获得明确指令，同时生成律师 brief；含糊回应不放行。
- 结论 🟡：逐条建议，改完复审。
- 含租期、续租、免租期、优先承租权行权期限的：提示并经用户同意后
  调用 `renewal-tracker`，把关键日期写入
  contracts/renewal-register.yaml。
- 全部条文引用过 `citation-audit`（G10）；未核验的保持 [CITE:__]
  占位，FAIL 状态不得外发。

## 常见误判与边界提示

1. **只看租金不看权属**：出租方不是产权人、转租链条断裂、房屋已
   抵押或被查封的，租金再优也是空中楼阁——权属核查在承租方视角
   是前置项，不是可选项。
2. **「二十年」分段续签的规避写法**：把三十年租期拆成「二十年 +
   自动续十年」的，续租部分的效力存疑 [模型知识—待核实]，标 🟡
   并建议律师介入，不当成确定性权利写进 memo。
3. **免租期不是免费期**：免租期内的物业费、能耗费、装修垃圾清运
   等承担未写明的，是 🟡 起步的标记项。
4. **押金的性质之争**：押金、保证金、违约金混用的，退还顺序与抵扣
   范围会在退租时爆发争议——要求按「担保范围 + 返还时限 + 抵扣
   程序」三件套核对。
5. **居住租赁与经营性租赁规则不同**：群租、隔断、居住房屋登记备案
   等行政监管要求 [模型知识—待核实]，经营性改造租赁单列合规提示。
6. **组合判断提示**：单条看不严重的条款组合起来可能构成 🔴——典型
   如出租方视角下「长租期 + 低递增 + 承租人可自由转租 + 装修残值
   归承租人」的组合。分桶先看组合、再看单项。

## 本技能不做什么

- 不代拟租赁合同条款语言——需起草的一律「建议转法务起草」。
- 不凭默认值给 🟢：playbook 未经律师审定时，结论天花板是 🟡。
- 不设硬编码阈值（押金几个月算高、免租期多长算长），一切比对画像/
  playbook 立场。
- 不替用户核查产权原件——提示应核的文件清单，核验动作由用户完成。
- 不替用户做租赁的商业决策（租不租、租金谈多少），只标风险与摩擦。
- 不处理 🔴 事项的后续（不出绕行方案，生成律师 brief 后停止）。
- 不做法律意见陈述：对非律师用户的全部输出受 G5 UPL 门控。
- 不直接手改画像：现场取得的立场经 `customize` 写回。

## 收尾与下一步

1. memo 交付后按第 7 步后果门分流：🔴 停止并转律师；🟡 修订后复审；
   🟢 走 G5 显式确认 + 律师 brief。
2. 含租期/续租/免租期/优先承租权期限 → `renewal-tracker` 登记
   contracts/renewal-register.yaml。
3. 全部引用过 `citation-audit`；条文原文经 `statute-verify` 核验
   （重点：第七百零五条、第七百二十五条填入正式引用前逐条核验）。
4. 需要业务方版本 → `contract-summary`（Quiet mode；上游严重度只作
   下限，降级须声明理由——G9）。
