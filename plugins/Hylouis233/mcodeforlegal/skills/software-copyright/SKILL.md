# 软件著作权登记材料准备

## 目的

把「要登一个软著」变成「材料清单 + 填写要点 + 补正预判」：按登记
机构的形式要求整理鉴别材料与权属证明，把申请表信息一次填对，把
常见补正原因提前排掉。

本技能的核心纪律有四条：

1. **官方口径优先**：材料规范、办理流程、时限费用以中国版权保护
   中心官网最新公布为准——本技能的流程描述全部标 [模型知识—
   待核实]，memo 中注明核对路径；
2. **权属先于材料**：软件是谁的没搞清楚，材料准备得再齐也是给
   别人做嫁衣——权属有疑义的先路由 `ip-assignment-review`；
3. **材料必须真实**：源程序与文档必须与真实软件一致；用户提出
   「凑页数」「改日期」的，按场景 A8.1 blocks 精神停止；
4. **登记是形式审查**：软著登记不作实质审查，证书是权属的初步
   证据而非绝对证明 [模型知识—待核实]——不在 memo 中夸大证书
   效力。

本技能遵守 legal-core Shared guardrails（G1–G12）与docs/scenes/ip-cn.md；冲突时以 legal-core 为准。

## 前置检查

1. 已按docs/scenes/ip-cn.md B1 完成画像检查与路由确认。
2. blocks 红线初扫（场景 A8.1）：软件来源可疑（如将他人软件改头
   换面登记为自有），停止并按 blocks 纪律处理。
3. 权属确认：自主开发 / 职务开发 / 委托开发 / 合作开发 / 继受
   取得——委托与合作开发的，权属约定是否明确；不明确的先路由
   `ip-assignment-review`。
4. 升级触发扫描（场景 B5）：涉外主体、登记目的涉诉讼举证——
   命中即升级。
5. 软件基本信息可读：名称、版本号、开发完成状态。

## 操作规程

### 第 0 步：Matter context（事项上下文）

- 查 `matters/_log.yaml`；多件登记或伴随版本迭代的，建议经
  `matter-workspace` 建档（一句提示即可，不强制）。

### 第 1 步：鉴别材料规范核对

登记申请需提交鉴别材料（源程序 + 文档）[模型知识—待核实，以
中国版权保护中心官网最新要求为准]：

1. **源程序**：一般提交前、后各连续 30 页；整个程序不足 60 页的，
   提交全部源程序 [模型知识—待核实]；
   - 每页行数、页眉标注（软件名称与版本号，与申请表一致）的
     形式要求 [模型知识—待核实]；
   - 页码连续、内容可读的排版要求；
   - 涉核心算法的遮盖处理安排（例外交存方式）[模型知识—待核实]；
2. **文档**：用户手册、操作手册、设计说明书等任选一种，前后各
   连续 30 页或全部 [模型知识—待核实]；
   - 文档中的软件名称、版本号、截图界面应与实际软件一致；
3. **一致性铁律**：源程序页眉、文档内容、申请表三处的软件全称
   与版本号必须完全一致——不一致是头号补正原因。

### 第 2 步：权属证明整理

按权利取得方式整理 [模型知识—待核实]：

- **自主/职务开发**：主体资格证明（营业执照等）；职务开发的
  劳动关系与任务分配证明（劳动合同、任务书、立项文件）——
  员工个人名义与单位名义登记的主体选择须与画像申请主体一致；
- **委托开发**：委托开发合同及其中权属约定条款；约定归委托方
  的，提交合同相关页；
- **合作开发**：合作开发合同及权属约定；共有软件的登记申请
  安排 [模型知识—待核实]；
- **继受取得**：转让合同或许可/继承证明。

权属约定不明的：不进入材料清单输出，先路由 `ip-assignment-review`
固定归属（work-but-ships，可经补充协议补救）。

### 第 3 步：申请表要点核对

逐项核对申请表信息 [模型知识—待核实，以官网最新表格为准]：

1. **软件全称/简称/版本号**：全称规范（一般以「软件」「系统」
   「平台」结尾 [模型知识—待核实]）；三处一致性见第 1 步；
2. **开发完成日期与首次发表日期**：日期逻辑（完成日不晚于发表
   日；未发表的如实选择）[模型知识—待核实]；日期倒签的按
   blocks 精神处理——如实填写；
3. **开发方式**：独立/合作/委托/下达任务开发，与权属证明对应；
4. **权利取得方式与权利范围**：原始取得/继受取得；全部权利/
   部分权利的选择含义 [模型知识—待核实]；
5. **技术信息**：硬件环境、软件环境、编程语言、源程序量（行数）
   ——与鉴别材料一致；
6. **申请人信息**：与主体资格证明完全一致（名称一字不差）。

### 第 4 步：常见补正原因预判

输出预判清单逐项自查（均 [模型知识—待核实]，以官网最新口径
为准）：

1. 页眉软件名称/版本号与申请表不一致；
2. 源程序页数不足或未按前后各 30 页连续提交；
3. 文档与软件实际功能明显不符、截图与名称对不上；
4. 开发完成日期与首次发表日期逻辑矛盾；
5. 权属证明缺失或与开发方式不对应；
6. 签章不规范（未盖章、章名与申请人不一致）；
7. 委托/代理手续不全。

### 第 5 步：输出材料清单

按下方模板输出：材料清单（每份材料标注形式要求与自查状态）、
申请表填写要点表、补正预判表。在线填报与材料寄送/上传动作由
用户完成——本技能不代办登记。

### 第 6 步：后果门（对应 G5）

- 用户为非律师：提交申请前走 G5 动作闸门——显式确认知悉后果
  （材料真实性责任、费用不因补正/不予登记退还的可能性
  [模型知识—待核实]）并获得明确指令，生成「带给律师的一页
  brief」（软件名称、权属链条、材料缺口、时间敏感性）。
- 命中 blocks 的：停止，brief 说明命中点，不推进。

### 第 7 步：收尾

- 引用过 `citation-audit`；未核验保持 [CITE:__]，FAIL 不得外发。
- 材料清单中所有形式要求注明「以中国版权保护中心官网最新要求
  为准」及核对日期。
- 向用户复述材料缺口与下一步，确认其理解。

## 输出模板

```markdown
【保密标头：按 G4 二选一】

# 软著登记材料清单：<软件名称及版本>

## Reviewer note
- 来源：<软件信息与权属材料 [用户提供]>
- 已读：<材料范围>
- 标记：🟢 齐备 / 🟡 需补正 / 🔴 不得推进（权属瑕疵或真实性风险）；
  单项 = 法律风险轴（🔴🟠🟡🟢）× 商业摩擦轴（阻碍/拖慢/费解/无感）
- 时效：<官方要求核查日期；未核验写"未核验——以版权保护中心官网
  最新要求为准">
- 使用前注意：<去向限制；非律师注明"本清单不是法律意见">
```

（正文：鉴别材料自查表 → 权属证明清单 → 申请表填写要点表 →
补正预判表 → [需复核] 清单 → 下一步）

## 常见误判与边界提示

1. **把软著登记当专利保护**：软著只保护代码与文档的表达，不保护
   技术方案本身——用户意图保护算法、架构的，提示路由
   `patent-disclosure-review` 评估专利路径，两者不互相替代。
2. **版本号管理混乱**：V1.0 登记后持续迭代却不登记新版本，证书
   与在售软件脱节；提示建立版本登记节奏，重大版本升级另行登记
   [模型知识—待核实]。
3. **开源组件混入鉴别材料**：源程序中大段第三方开源代码未剔除
   或未标注的，既可能引发补正疑问，也可能暴露许可证合规问题
   [模型知识—待核实]——准备鉴别材料时如实处理，不遮掩。
4. **登记主体与实际经营主体错位**：集团内研发在 A 公司、运营在
   B 公司，证书主体与维权/资质申报主体不一致时后续麻烦多——
   主体选择提示与画像申请主体对齐，错位风险列入 [需复核]。
5. **APP、小程序、游戏的材料特殊性**：涉及版号、上架资质联动
   需求的，提示该等资质另有监管要求 [模型知识—待核实]，软著
   证书不替代任何行政许可。

## 本技能不做什么

- 不代办登记、不代填在线申请系统——准备材料与要点，提交动作由
  用户完成。
- 不保证下证时长与结果——审查进度以登记机构为准。
- 不夸大登记效力：证书是权属初步证据，不替代对软件来源的实质
  审查。
- 不审查代码本身的侵权风险（如开源组件许可证冲突）——提示另行
  评估，属专项。
- 不协助材料造假（凑页数、倒签日期、冒名登记）——命中 blocks
  即停止。
- 不设硬编码「几天下证」「多少钱」——时限费用以官网为准
  [需复核]。
- 不做法律意见陈述：对非律师用户的全部输出受 G5 UPL 门控。

## 收尾与下一步

1. 材料清单交付后按第 6 步后果门走 G5 显式确认 + 律师 brief。
2. 全部引用过 `citation-audit`；条文核验经 `statute-verify`。
3. 权属不明的，先路由 `ip-assignment-review` 固定归属（补充协议
   补救属 work-but-ships）。
4. 收到补正通知的，按第 4 步预判表定位原因，逐项补正后重新
   核对。
5. 软件含开源组件的，提示另行评估许可证义务（GPL 系组件的
   传染性等 [模型知识—待核实]），建议咨询律师。
6. 登记完成后，提示经 `matter-workspace` 归档证书信息与登记号，
   版本迭代时复用本技能。
