# 服务/委托合同专项审查

## 目的

把一份服务合同从「看报价和人天」变成「按本方立场逐项过堂」：确认审查
视角（委托方/服务方），用经确认的 playbook 立场逐项比对，把结果分成
🟢🟡🔴 三桶，产出一份可直接行动（改、谈、签、停）的 triage memo。

本技能的核心纪律有三条：

1. **范围先于价格**：服务合同的第一高发争议是范围蔓延——服务范围
   界定不清时，SLA、验收、价款全部失去锚点；
2. **结论依附立场**：同一条 SLA 考核对委托方是质量抓手、对服务方是
   扣款风险敞口，不先定立场就无权下结论；
3. **🟢 不出自默认值**：🟢 只能基于律师审定的 playbook 立场；画像里
   还是默认模板时，单份合同最高 🟡（docs/scenes/contract-review-cn.md B3）。

本技能遵守 legal-core Shared guardrails（G1–G12）与docs/scenes/contract-review-cn.md；冲突时以 legal-core 为准。

## 前置检查

1. 已由 `contract-review` 路由器完成画像检查与路由确认；未经路由器直接进来
   的先补齐。
2. 文本完整可读；服务说明书（SOW）、SLA 附件、报价单、工单模板不齐
   的，在 reviewer note 的「已读」行如实写明。
3. 用户角色已识别，决定 G4 标头档位与 G5 后果门口径。
4. 金额初判：合同金额是否超过画像的合同审批金额阈值——超过即触发
   B5 升级，memo 照出但明示「须升级人工」。

## 操作规程

### 第 0 步：Matter context 与 Destination check

- Matter context：查 `matters/_log.yaml`；已有相关事项则挂入（memo
  存 drafts/，notes.md 追加进展）；长期服务关系或框架协议的，建议经
  `matter-workspace` 建档（提示即可，不强制）。
- Destination check：产物去向在保密圈外的 flag 并可提供内外双版本；
  memo 含本方预算底线、SLA 容忍度等立场信息，外泄直接损害谈判地位。
  去向不明按仅内部处理。

### 第 1 步：立场判定（委托方 / 服务方）

- **委托方视角**重点：服务范围是否封闭（防范围蔓延与另行收费）；SLA
  是否可考核可举证；关键人员是否锁定；验收抓手；服务成果知识产权
  归属；退出与交接安排。
- **服务方视角**重点：服务范围是否开口（「等相关服务」式表述）；SLA
  指标是否在己方可控范围（依赖委托方配合的指标要免责衔接）；变更
  与加价的机制是否顺畅；付款节点与验收是否脱钩风险；责任上限；
  背景 IP 不被裹挟。
- 两个视角都查「义务对等性」：逾期付款责任与服务不达标责任是否
  对称。
- 文本角色与业务实质不一致的（如名为服务实为劳务派遣、名为委托实为
  买卖），以业务实质为准，在 memo 中说明，并评估是否需向用户提出
  类型重路由。

### 第 2 步：加载 playbook（服务立场）

- 读取画像中的服务合同立场节；经律师审定的直接使用，默认模板最高
  🟡。
- 未填的，现场询问关键立场并**经 `customize` 技能写回画像**（标
  [已确认—日期]、「未经律师审定」）：
  1. 服务成果知识产权归属底线（委托方视角：是否必须取得成果权利；
     服务方视角：哪些背景 IP 与通用方法绝不转让）；
  2. 可接受的 SLA 考核与扣罚结构（具体指标由用户给出，本技能不
     提供硬编码阈值）；
  3. 关键人员锁定的容忍度；
  4. 付款节奏与验收挂钩的立场；
  5. 管辖偏好（与 B9 首选管辖对齐）。
- 用户答不出：不编造，相关项整体 🟡，理由「立场未确认」。

### 第 3 步：Scope check（类型辨析与藏条款，无条件执行）

通读全文，完成两件事：

**（a）类型辨析**：多数「服务合同」属无名合同，适用合同编通则并参照
最相类似的有名合同规则 [模型知识—待核实，引用前经 statute-verify
核验]；名为委托合同的，落入委托合同章（委托合同定义与任意解除权
[模型知识—待核实，引用前经 statute-verify 核验]）；行纪、中介（原
居间）各有专门规则 [模型知识—待核实]。类型辨析结论写入 reviewer
note，它决定解除权与费用规则的审查口径。

**（b）藏条款识别**：命中以下任一情形，**无条件 auto-🟡** 并在执行
摘要第一行明示「本合同名为服务/委托合同，实际含有 XX 安排」：

1. **名为服务实为劳务派遣/劳动关系**：人员由委托方直接管理、考勤、
   定薪——涉劳动法风险，不按本清单审，提示走劳动法律师渠道
   [模型知识—待核实]。
2. **名为服务实为买卖或承揽**：按成果件数计价、交付标准化产品——
   按买卖/承揽逻辑另列标记项。
3. **夹带竞业与排他**：限制服务方承接同类客户、限制委托方另行采购。
4. **夹带不招揽**：限制聘用对方员工，范围与期限过宽时影响用人自由。
5. **代为处分类委托中的越权外观**：委托事项含代收代付、代签文件的，
   授权边界不清即重大风险。

处理方式：藏条款部分按真实法律关系另列标记项（起点 🟡）；命中画像
红线条款的按画像红线纪律（出现即提示，严重度下限 🟠，G9）。

### 第 4 步：分类检查清单（七类，调用 risk-clause-database）

逐类检查。**不设硬编码数值阈值**——SLA 指标高低、扣罚比例、响应
时限一律比对画像/playbook 立场；立场未覆盖的标 🟡 写「超出 playbook」。
通用条款风险形态调用 `risk-clause-database` 取统一口径，本节只列
服务专项要点：

1. **服务范围界定（防范围蔓延）**：范围描述是封闭式列举还是「包括但
   不限于」的开口表述；服务说明书（SOW）是否附件化并与正文效力顺位
   明确；范围外事项的变更与计价机制（变更单流程）；委托方视角防
   「这也要加钱」，服务方视角防「这也在范围内」。
2. **SLA 服务标准与考核**：指标是否客观可测量（响应时间、可用率、
   交付及时率）；测量方法与数据来源（谁的数据说了算）；未达标的
   后果梯度（整改—扣减服务费—解除）；扣罚与违约金的关系（是否
   互为替代或叠加）；依赖委托方配合事项的免责衔接。
3. **人员投入与关键人员锁定**：投入人员数量、资质、工时是否写明；
   关键人员名单制与更换限制（更换须经同意、同等资历替换）；服务方
   视角争取合理的替换空间，委托方视角防「签约是 A 团队、干活是 B
   团队」；分包限制。
4. **验收标准与流程**：阶段验收与最终验收的标准、期限、程序；「逾期
   未提异议视为验收合格」的默示验收——委托方视角争取删除或延长，
   服务方视角争取写上；验收不通过的返工与费用；部分验收与整体
   验收的关系。
5. **知识产权归属（服务成果/背景 IP 区分）**：服务成果归属约定；
   **背景 IP 与前景 IP 是否分开**——「为履约产生的一切成果归甲方」
   会把服务方的通用方法、工具、模板裹挟进去，服务方视角高危；归属
   委托方时服务方的保留使用权（内部复用、通用技术积累）；委托方
   提供的资料、数据的权属与使用边界。
6. **保密**：双方保密义务的范围、例外、期限；委托方数据与个人信息
   的处理边界（涉及个人信息处理的，提示数据合规专项，不展开）；
   服务结束后资料的返还与删除。
7. **违约、解除与争议解决**：违约情形是否覆盖服务特有形态（SLA
   连续不达标、关键人员流失、泄密）；责任上限是否对等（对照民法典
   第五百七十七条 [CITE:__] 与画像赔偿上限立场）；**委托合同的任意
   解除权**——委托人或受托人可以随时解除委托合同，解除的赔偿范围
   区分有偿/无偿（民法典第九百三十三条相关 [模型知识—待核实，引用
   前经 statute-verify 核验]）——名为委托或实质为委托关系的合同，
   任意解除权能否排除或限制是核心审查点；解除后果（已履行部分结算、
   资料交接、过渡期服务）是否写全；管辖对照画像首选管辖。

红线扫描：全量对照docs/scenes/contract-review-cn.md A8.1 的 blocks 与画像红线。服务
场景的高发区：以服务外观行劳务派遣之实规避用工责任、无资质承接
特许业务（如医疗、金融、教育服务资质）、阴阳价格文本。命中即停止
并明示。

### 第 5 步：分桶 🟢🟡🔴

- **🟢 可推进**：七类全部落在经律师审定的 playbook 立场内；默认
  模板立场最高 🟡。
- **🟡 需修订或需人判断**：偏离 playbook 但可修；playbook 未覆盖；
  命中 Scope check 藏条款；范围界定开口需收口。
- **🔴 不得推进**：命中 blocks 红线或画像审批底线；或条款组合构成
  重大不利且不可经修改补救（如服务方视角下「范围全开口 + SLA 无
  上限扣罚 + 背景 IP 被裹挟 + 委托方可任意解约不赔偿」的组合）。
- **双轴标注**：每项同时按 G9 给法律风险轴（🔴🟠🟡🟢）与商业摩擦轴
  （阻碍/拖慢/费解/无感）。分桶时先看组合、再看单项。

### 第 6 步：输出 memo

使用统一 triage memo 模板（见下方）。执行摘要只放机械性一行修改；
凡是需要起草新语言的（重写范围条款、补 SLA 考核机制），建议栏只写
「**建议转法务起草**」，不在 memo 里代拟。

### 第 7 步：后果门与收尾

- 结论含 🔴：memo 首页明示「**本合同不提交签署流程、不向相对方作出
  任何承诺**」，按 G5 生成「带给律师的一页 brief」，非律师用户到此
  停止。
- 结论 🟢 且用户为非律师：进入签署流程前按 G5 动作闸门——显式确认
  知悉后果并获得明确指令，同时生成律师 brief；含糊回应不放行。
- 结论 🟡：逐条建议，改完复审。
- 含服务期限、SLA 考核周期、自动续期、续约通知期的：提示并经用户
  同意后调用 `renewal-tracker` 登记 contracts/renewal-register.yaml。
- 全部条文引用过 `citation-audit`（G10）；未核验的保持 [CITE:__]
  占位，FAIL 状态不得外发。

## 常见误判与边界提示

1. **范围条款「包括但不限于」**：开口表述叠加「甲方要求的其他相关
   服务」，服务方的报价模型会整体失效——范围收口是第一优先标记项。
2. **SLA 指标不在己方可控范围**：指标依赖委托方提供数据、场地、
   决策的，没有免责衔接条款，服务方等于签了无限扣款承诺。
3. **任意解除权的惊讶效应**：名为委托或实质为委托关系的，对方可能
   依法随时解除（第九百三十三条相关 [模型知识—待核实]）；长期投入
   型服务（前期投入大、后期回本）尤其要核查解除后的结算与赔偿。
4. **框架协议不看工单**：框架 + 工单结构的，范围、价格、SLA 常分散
   在两级文件，冲突顺位未约定的，是 🟡 起步的标记项；缺件按缺件
   如实记录。
5. **把保密章当全部合规**：服务方接触委托方数据的，保密条款之外
   还有数据合规义务边界——提示数据合规专项，本技能不展开。
6. **组合判断提示**：单条看不严重的条款组合起来可能构成 🔴——典型
   如委托方视角下「范围封闭但验收主观 + 关键人员不锁定 + 服务方
   责任上限极低 + 无退出交接安排」的组合。分桶先看组合、再看单项。

## 本技能不做什么

- 不代拟服务合同条款语言——需起草的一律「建议转法务起草」。
- 不凭默认值给 🟢：playbook 未经律师审定时，结论天花板是 🟡。
- 不设硬编码阈值（SLA 扣罚比例多少算高、响应时限多长算合理），
  一切比对画像/playbook 立场。
- 不就劳动法、数据合规下结论——涉及时提示对应专项或律师渠道。
- 不替用户做采购/外包的商业决策，只标风险与摩擦。
- 不处理 🔴 事项的后续（不出绕行方案，生成律师 brief 后停止）。
- 不做法律意见陈述：对非律师用户的全部输出受 G5 UPL 门控。
- 不直接手改画像：现场取得的立场经 `customize` 写回。

## 收尾与下一步

1. memo 交付后按第 7 步后果门分流：🔴 停止并转律师；🟡 修订后复审；
   🟢 走 G5 显式确认 + 律师 brief。
2. 含服务期限/SLA 考核周期/自动续期/续约通知期 → `renewal-tracker`
   登记 contracts/renewal-register.yaml。
3. 全部引用过 `citation-audit`；条文原文经 `statute-verify` 核验
   （重点：第九百三十三条任意解除权规则的现行文本）。
4. 需要业务方版本 → `contract-summary`（Quiet mode；上游严重度只作
   下限，降级须声明理由——G9）。
5. 长期服务关系的，提示经 `matter-workspace` 建档，后续工单、变更
   单挂同一事项 slug。
6. 审查中发现画像服务立场缺失或覆盖不全的，提示经 `customize` 完善
   playbook——playbook 越完整且经律师审定，未来给出 🟢 的空间越大。
