# 技术交底书审查

## 目的

把一份技术交底书从「技术描述」变成「可交付代理师的申请候选」：提炼
发明点、选对专利类型、做新颖性创造性的初筛与检索安排、核对交底书
完整性、排查申请前公开风险，输出结构化审查意见。

本技能的核心纪律有四条：

1. **模型不代替检索**：新颖性、创造性判断依赖现有技术检索，本技能
   输出检索策略（关键词、分类号、渠道），实际检索由用户在官方或
   商业系统人工执行；不声称已检索、不把训练记忆当作检索结果；
2. **申请日前保密优先**：交底内容一旦在申请日前公开可能永久破坏
   新颖性 [模型知识—待核实，引用前经 statute-verify 核验]——
   保密提示无条件出现在每份审查意见中；
3. **不代写权利要求**：权利要求书撰写是专利代理师的核心专业工作，
   本技能只到交底书质量与发明点提炼为止；
4. **不承诺授权**：审查意见是申请准备质量评估，不是授权前景保证。

本技能遵守 legal-core Shared guardrails（G1–G12）与docs/scenes/ip-cn.md；冲突时以 legal-core 为准。

## 前置检查

1. 已按docs/scenes/ip-cn.md B1 完成画像检查与路由确认。
2. blocks 红线初扫（场景 A8.1）：交底内容疑似来源于原单位或第三方
   保密信息的（用户自述或材料显示来源可疑），停止并按 blocks
   纪律处理。
3. 升级触发扫描（场景 B5）：涉外布局（PCT 等）、诉讼中、高价值
   专利组合、职务发明归属有争议迹象——命中即升级。
4. 保密状态确认：交底书是否已在论文、展会、销售、试用、众筹等
   渠道公开——影响新颖性判断，必须先问。
5. 文本完整可读；附图缺失的，在 reviewer note「已读」行写明。

## 操作规程

### 第 0 步：Matter context（事项上下文）

- 查 `matters/_log.yaml`；专利申请伴随期限链条（优先权、答复期），
  建议经 `matter-workspace` 建档（一句提示即可，不强制）。

### 第 1 步：发明点提炼

从交底书中提炼可保护的技术贡献，输出「问题—手段—效果」三行式：

- **要解决的技术问题**：相对于最接近的现有方案，本方案改善什么；
- **技术手段**：实现改善的核心技术特征——与现有技术的**区别
  特征**是发明点的锚；
- **技术效果**：区别特征带来的可验证效果。

交底书写成「产品功能说明书」而无技术实现细节的，发明点无法锚定，
🟡 起步并列出需要补充的技术信息清单。一价交底包含多个独立发明点
的，提示分案可能性 [模型知识—待核实]。

### 第 2 步：专利类型选择

三种类型比对（保护客体与路径差异 [模型知识—待核实，引用前经
statute-verify 核验]）：

| 类型 | 保护客体 | 特点 |
| --- | --- | --- |
| 发明 | 产品、方法或其改进的技术方案 | 实质审查，保护期较长，周期较长 |
| 实用新型 | 产品的形状、构造或其结合 | 初步审查，周期短，不保护方法 |
| 外观设计 | 产品整体或局部的形状、图案、色彩等富有美感并适于工业应用的新设计 | 初步审查，保护外观不保护技术 |

选择建议：方法方案只能走发明；产品结构可发明/实用新型（同日双申
策略的存在与利弊 [模型知识—待核实]）；纯外观改进走外观设计。
类型选择影响后续全部准备，用户拍板前在 memo 中并列呈现选项。

### 第 3 步：新颖性创造性初筛（检索人工执行）

- **初筛**：基于交底书自述的背景技术与用户提供的行业认知，做
  定性初筛——区别特征是否属于公知常识的浅层组合 [模型知识—
  待核实]；初筛意见标注为初步判断；
- **检索策略输出**：核心关键词（中英文）、近义词扩展、可能的
  IPC/CPC 分类号方向 [需复核]、检索渠道建议——国知局专利检索
  及分析系统（官方免费）、商业数据库（如 incopat、智慧芽等，
  按用户已有条件选择）；
- **检索执行**：由用户或代理师人工执行；本技能可协助整理用户
  粘贴的检索结果 [用户提供] 并做对比分析，但不代替检索动作；
- **抵触申请提示**：他人在先申请、在后公开的申请可破坏新颖性
  [模型知识—待核实，引用前经 statute-verify 核验]——检索需
  覆盖最新公开文献；
- **结论口径**：未经人工检索复核的，审查意见最高 🟡（场景 B3）。

### 第 4 步：交底书完整性核对

按五要件逐项核对（充分公开是「以公开换保护」的对价 [模型知识—
待核实]）：

1. **技术领域**：一句话定位所属技术领域；
2. **背景技术**：现有方案及其缺陷——是否引用了具体现有技术
   （论文、专利、产品），还是泛泛而谈；
3. **发明内容**：技术问题、技术方案、有益效果三者是否闭环；
4. **具体实施方式**：至少一个可落地的实施例——本领域技术人员
   能否据以实施；关键参数、结构关系、流程步骤是否给出；
5. **附图及说明**：结构类方案是否有附图，附图标记是否与文字
   对应。

缺项列入补正清单，写明「向研发同事补充什么信息」。

### 第 5 步：申请前公开风险排查（无条件执行）

逐项询问/排查申请日前的公开渠道 [模型知识—待核实，引用前经
statute-verify 核验]：

- 论文发表、学术会议报告、学位论文公开；
- 展会展示、产品发布、销售、试用、众筹；
- 网站/公众号/视频平台公开、招标投标文件披露；
- 合作方尽调中的未签保密协议的披露。

已发生公开的：评估公开时间与内容，提示法定的不丧失新颖性例外
情形范围很窄 [模型知识—待核实，引用前经 statute-verify 核验]，
属 work-but-ships（可补救评估但不得保证）；公开严重且不满足
例外的，如实写明授权前景重大风险（🔴 起步），建议咨询专利
代理师。未发生公开的：memo 写入保密要求——申请日前不得以上述
任何方式公开，对外交流一律先签保密协议。

### 第 6 步：输出审查意见

按下方模板输出，结论分级：

- **🟢 可交付代理师**：发明点清晰、类型明确、交底五要件齐备、
  无公开风险、人工检索已复核且无破坏性文献；
- **🟡 需补充或需人判断**：交底缺项可补、检索未复核、类型选择
  待定；
- **🔴 暂不推进**：命中 blocks、申请前公开已实质破坏新颖性迹象、
  权属有争议迹象（联动 `ip-assignment-review`）。
- 每个标记项按 G9 双轴标注。

### 第 7 步：后果门（对应 G5）

- 用户为非律师：向代理机构或官方提交前走 G5 动作闸门——显式
  确认知悉后果（含「提交即启动公开倒计时」「费用不因驳回退还」）
  并获得明确指令，生成「带给律师/代理师的一页 brief」（发明点
  三行式、类型建议、检索缺口、保密要求、时间敏感性）。
- 命中 blocks 的：停止，brief 说明命中点，不推进。

### 第 8 步：收尾

- 引用过 `citation-audit`；未核验保持 [CITE:__]，FAIL 不得外发。
- 交底书按仅内部材料管理（场景 A7）；关键期限（优先权期限等
  [模型知识—待核实]）提示记入事项节点。
- 向用户复述保密要求与下一步，确认其理解。

下一步）

## 本技能不做什么

- 不代写权利要求书、说明书定稿——属专利代理师工作。
- 不代替人工检索，不声称已检索官方或商业数据库。
- 不承诺授权前景（「肯定能授权」一律不说）。
- 不做 FTO（自由实施）分析、不做侵权比对——属专项，命中即按
  场景 B5 升级。
- 不处理涉外申请（PCT、巴黎公约途径）细节——命中即升级。
- 不协助将来源可疑的技术信息包装为自有成果——命中 blocks 即停止。
- 不做法律意见陈述：对非律师用户的全部输出受 G5 UPL 门控。

## 收尾与下一步

1. 审查意见交付后按第 7 步后果门走 G5 显式确认 + 律师/代理师
   brief。
2. 全部引用过 `citation-audit`；条文核验经 `statute-verify`。
3. 权属未固定的（职务发明、合作研发背景），先路由
   `ip-assignment-review` 固定归属再推进申请。
4. 人工检索完成后，提示将结果 [用户提供] 回填，更新初筛意见。
5. 交底补齐后重新过本技能第 4 步完整性核对。
6. 发明点提炼与布局结论建议经 `customize` 写回画像，供后续
   交底复用。
