# 借款合同专项审查

## 目的

把一份借款合同从「看利率高不高」变成「按本方立场逐项过堂」：先定性
（民间借贷还是金融借款、是真借款还是藏了别的法律关系），确认审查视角
（出借方/借款方），用经确认的 playbook 立场逐项比对，把结果分成
🟢🟡🔴 三桶，产出一份可直接行动（改、谈、签、停）的 triage memo。

本技能的核心纪律有三条：

1. **定性先于条款**：民间借贷与金融借款的利率规则、监管框架不同；名为
   借款实为投资、合伙、货款转化的，按真实法律关系另审，不套借款清单；
2. **结论依附立场**：同一条提前还款条款对出借方是回款安排被打乱、对
   借款方是资金调度自由，不先定立场就无权下结论；
3. **🟢 不出自默认值**：🟢 只能基于律师审定的 playbook 立场；画像里
   还是默认模板时，单份合同最高 🟡（docs/scenes/contract-review-cn.md B3）。

本技能遵守 legal-core Shared guardrails（G1–G12）与docs/scenes/contract-review-cn.md；冲突时以 legal-core 为准。

## 前置检查

1. 已由 `contract-review` 路由器完成画像检查（无 [填空]）与路由确认（用户已
   认可借款合同类型）；未经路由器直接进来的先补齐。
2. 文本完整可读；借条、转账凭证、还款计划表、担保合同等附件不齐的，
   在 reviewer note 的「已读」行如实写明范围。
3. 用户角色已识别（律师/法务/业务/其他），决定 G4 标头档位与 G5
   后果门口径；画像未完成时按非律师档处理。
4. 金额初判：借款金额是否超过画像的合同审批金额阈值；本方对外提供
   担保是否在画像审批底线清单内——命中即触发 B5 升级，memo 照出但
   明示「须升级人工」。

## 操作规程

### 第 0 步：Matter context 与 Destination check

- Matter context：查 `matters/_log.yaml`（登记簿 schema 以 legal-core
  的 `matter-workspace` 为准）；已有相关事项则挂入（memo 存 drafts/，
  notes.md 追加进展）；可能伴随多轮谈判或分期履行的，建议经
  `matter-workspace` 建档（提示即可，不强制）。
- Destination check：产物去向在保密圈外的 flag 并可提供内外双版本；
  memo 含本方资金成本底线、担保要求等立场信息，外泄直接损害谈判地位。
  去向不明按仅内部处理，并在 memo 头部注明「未经确认不得外发」。

### 第 1 步：立场判定（出借方 / 借款方）

判定本方在合同中的角色：

- **出借方视角**重点：本金是否实际交付并可举证（转账留痕）；借款人
  主体资信与还款来源；担保是否落实（保证人签署、抵押/质押登记、公司
  担保决议）；违约与加速到期触发条件是否顺手；管辖是否便利。
- **借款方视角**重点：实际到手本金是否与合同一致（砍头息迹象）；
  综合资金成本（利息之外的服务费、保证金、咨询费等隐性负担）；提前
  还款是否自由；违约触发条件是否过宽（交叉违约、财务指标约束）；加速
  到期是否被滥用。
- 两个视角都查「义务对等性」：逾期利率、违约金只压一方的，本身就是
  标记项。
- 文本角色与业务实质不一致的（如名为借款实为固定回报的投资安排），
  以业务实质为准，在 memo 中说明，并评估是否需向用户提出类型重路由。

### 第 2 步：加载 playbook（借款立场）

- 读取画像中的借款合同立场节；画像无该节时，先核对画像「红线条款与
  审批底线」中关于利率、担保、对外借款/对外担保的条目。经律师审定的
  立场直接使用；仍是默认模板的，分桶最高 🟡 并在 memo 中明示。
- 未填的，现场询问关键立场并**经 `customize` 技能写回画像**（标
  [已确认—日期]、「未经律师审定」）：
  1. 可接受的利率区间与综合资金成本上限（具体数字由用户给出，本技能
     不提供硬编码阈值）；
  2. 是否接受任何形式的前置扣费（砍头息属原则问题，不接受即红线）；
  3. 担保要求——出借方视角：必须取得何种担保；借款方视角：可否接受
     连带责任保证、实控人个人连带；
  4. 提前还款安排与对应补偿的立场；
  5. 管辖偏好（与 B9 首选管辖对齐）。
- 用户拒答或答不出：不编造立场，相关检查项整体 🟡，理由写「立场未
  确认」。

### 第 3 步：Scope check（定性与藏条款，无条件执行）

通读全文，识别定性错误与藏条款。命中第 2–4 项的**无条件 auto-🟡**
并在执行摘要第一行明示；命中第 5、6 项的按docs/scenes/contract-review-cn.md A8.1
blocks 处理：停止、明示、建议转律师：

1. **民间借贷 / 金融借款定性**：出借方是否为金融机构或持牌放贷主体。
   两类适用不同的利率规则与监管框架 [模型知识—待核实，引用前经
   statute-verify 核验]；定性错误会导致整条利率检查口径失效。
2. **名为借款实为投资/合伙**：约定固定回报但文本带有共担风险、参与
   经营外观，或回报与经营成果挂钩——实为投资或合伙关系，借款检查
   清单不再适用。
3. **由其他款项转化而来**：借款由货款、工程款、股权款对账转化（常见
   的「对账转借条」）——基础法律关系影响利率规则的适用与举证结构
   [模型知识—待核实]。
4. **职业放贷迹象**：出借方频繁对外放贷、以此为业——职业放贷背景下
   借款合同效力存在重大风险 [模型知识—待核实，引用前经
   statute-verify 核验]。
5. **阴阳利率**：口头利率与书面利率系统性背离、两套文本，或另行签订
   「服务费协议」抬高综合成本以规避利率上限——虚假意思表示迹象，
   按 blocks 第 1 项处理。
6. **借借款外观规避监管**：如规避外汇、税务、金融准入监管（blocks
   第 4 项）。

处理方式：藏条款部分不按借款条款清单审查，按真实法律关系另列标记项
（起点 🟡）；命中画像红线条款的按画像红线纪律（出现即提示，严重度
下限 🟠，G9）。

### 第 4 步：分类检查清单（六类，调用 risk-clause-database）

逐类检查。**不设硬编码数值阈值**——利率高低、期限长短、违约金比例
一律比对画像/playbook 立场与经核验后的法定上限；立场未覆盖的标 🟡
写「超出 playbook」。通用条款风险形态调用 `risk-clause-database`
取统一口径，本节只列借款专项要点：

1. **本金与交付**：本金数额、币种、交付时间与方式（转账留痕；现金
   交付的举证风险）；**实际到账金额与合同本金是否一致**——利息预先
   在本金中扣除的，按实际出借数额认定本金并计算利息（民法典第六百
   七十条 [CITE:__]）；「保证金」「服务费」「咨询费」等名义的前置
   扣费，实质可能是变相砍头息，并入综合成本测算。自然人之间的借款
   合同自贷款人提供借款时成立（民法典第六百七十九条相关
   [模型知识—待核实，引用前经 statute-verify 核验]）——尚未放款的，
   合同可能未成立。
2. **利率与利息**：利率表述是年利率还是月利率、单利还是复利；借期内
   利率、逾期利率、违约金是否叠加及叠加后的综合水平。**民间借贷利率
   的司法保护上限采一年期贷款市场报价利率（LPR）四倍规则
   [模型知识—待核实，引用前必须经 statute-verify 核验]**——引用该
   上限前必须运行 `statute-verify` 核验现行司法解释文本与 LPR 取值
   口径，未核验不得在 memo 中写死任何数值；金融借款的利率规则不同，
   不适用该上限 [模型知识—待核实]。禁止高利放贷（民法典第六百八十条
   [CITE:__]）。利息支付节点；利率无约定或约定不明时的法定处理
   [模型知识—待核实]。
3. **期限、还款方式与提前还款**：借款期限与到期日是否明确；还款方式
   （到期一次性还本付息 / 等额本息 / 等额本金 / 先息后本）与按合同
   利率的实测是否一致；提前还款是否允许、是否收违约金或补偿金——
   借款方视角争取提前还款自由，出借方视角关注资金安排被打乱的补偿；
   分期还款中任一期逾期对全案的影响（与第 5 类加速到期衔接）。
4. **担保条款衔接**：有无保证、抵押、质押；保证方式是否写明（约定
   不明时的法定推定 [模型知识—待核实，引用前经 statute-verify
   核验]）；保证期间是否约定及其长短；抵押/质押的登记安排与担保
   范围；公司对外提供担保的内部决议要求 [模型知识—待核实]——出借
   方视角应核查担保人决议文件，否则担保效力存在风险；主从合同的
   效力衔接 [模型知识—待核实]。担保文件不齐的按缺件如实记录。
5. **违约与加速到期**：违约情形列举是否清晰、是否单方倾斜；交叉
   违约、财务指标约束、资金用途监管条款（借款人未按约定用途使用
   借款时出借人的救济 [模型知识—待核实，引用前经 statute-verify
   核验]）；加速到期的触发条件、通知程序与后果（全部本息提前到期
   + 逾期利率起算）；借款方视角重点防「轻微违约即全额加速」；逾期
   利息与违约金并存的综合负担是否畸高（司法调整空间
   [模型知识—待核实]）。
6. **管辖与争议解决**：法院或仲裁、地点，对照画像首选管辖；借款
   纠纷地域管辖的确定规则 [模型知识—待核实]；主合同与担保合同的
   管辖约定是否一致；涉外因素的准据法（按 G3 法域识别五步处理）。

红线扫描：全量对照docs/scenes/contract-review-cn.md A8.1 的 blocks 与画像红线。借款
场景的高发区：阴阳利率文本、变相砍头息、高利放贷、为无资质主体
规避金融准入、担保链中的虚假意思表示。命中即停止并明示。

### 第 5 步：分桶 🟢🟡🔴

- **🟢 可推进**：六类检查项全部落在经律师审定的 playbook 立场之内。
  默认模板立场不得给 🟢，最高 🟡。
- **🟡 需修订或需人判断**：偏离 playbook 但可修；playbook 未覆盖；
  命中 Scope check 第 2–4 项；定性或利率口径待核验。
- **🔴 不得推进**：命中 blocks 红线或画像审批底线；或条款组合构成
  重大不利且不可经修改补救（如借款方视角下「砍头息 + 复利计息 +
  轻微违约即全额加速 + 实控人个人无限连带」的组合）。
- **双轴标注**：每个标记项同时按 G9 给法律风险轴（🔴🟠🟡🟢）与商业
  摩擦轴（阻碍/拖慢/费解/无感）。分桶时先看组合、再看单项。

### 第 6 步：输出 memo

使用统一 triage memo 模板（见下方）。执行摘要只放机械性一行修改；
凡是需要起草新语言的（重写利率条款、补担保衔接安排），建议栏只写
「**建议转法务起草**」，不在 memo 里代拟。

### 第 7 步：后果门与收尾

- 结论含 🔴：memo 首页明示「**本合同不提交签署流程、不向相对方作出
  任何承诺**」，按 G5 生成「带给律师的一页 brief」，非律师用户到此
  停止。
- 结论 🟢 且用户为非律师：进入签署/放款流程前按 G5 动作闸门——显式
  确认知悉后果并获得明确指令，同时生成律师 brief；含糊回应不放行。
- 结论 🟡：逐条给出修改建议或「建议转法务起草」，改完可重新过一遍
  本技能。
- 含还款计划、担保期间、展期安排的：提示并经用户同意后调用
  `renewal-tracker`，把到期日写入 contracts/renewal-register.yaml。
- 全部条文引用过 `citation-audit`（G10）；未核验的保持 [CITE:__]
  占位，FAIL 状态不得外发。

## 常见误判与边界提示

1. **借条不等于借款合同全貌**：只有借条没有借款合同时，交付凭证、
   还款记录、聊天记录都是认定本金与利率的材料；已读范围如实写明，
   不把「只有一张借条」当「没有风险」。
2. **「月息 X 分」的换算歧义**：分/厘口径在年利率换算中歧义高发，
   一律要求换算成年利率并标 [需复核]，不凭习惯直接采信某一换算。
3. **主体混同**：法定代表人以个人名义借款用于公司经营、或夫妻一方
   举债的，债务人范围与共同债务认定是独立问题 [模型知识—待核实]，
   超出 playbook 时标 🟡 并建议律师介入。
4. **借新还旧对担保的影响**：借新还旧安排下担保责任的变化
   [模型知识—待核实，引用前经 statute-verify 核验]——出借方视角
   重点核查，不能默认担保自然延续。
5. **网贷/平台借款文本**：格式条款占比高、几乎没有谈判空间；按本
   技能审查，同时提示「不接受可能影响授信」的商业摩擦（商业摩擦轴：
   阻碍），由业务负责人拍板。
6. **组合判断提示**：单条看不严重的条款组合起来可能构成 🔴——典型
   如借款方视角下「前置扣费 + 高逾期利率 + 交叉违约 + 全额加速 +
   个人连带」的组合。分桶先看组合、再看单项。

## 本技能不做什么

- 不代拟借款合同或担保条款语言——需起草的一律「建议转法务起草」。
- 不凭默认值给 🟢：playbook 未经律师审定时，结论天花板是 🟡。
- 不写死利率上限数值：LPR 四倍规则未经 `statute-verify` 核验前，
  memo 中只给口径说明，不给数字。
- 不设硬编码阈值（利率多少算高、期限多长算长），一切比对画像/
  playbook 立场与经核验的法定上限。
- 不替用户做放款/借款的商业决策，只标风险与摩擦。
- 不处理 🔴 事项的后续（不出绕行方案，生成律师 brief 后停止）。
- 不做法律意见陈述：对非律师用户的全部输出受 G5 UPL 门控。
- 不直接手改画像：现场取得的立场经 `customize` 写回。

## 收尾与下一步

1. memo 交付后按第 7 步后果门分流：🔴 停止并转律师；🟡 修订后复审；
   🟢 走 G5 显式确认 + 律师 brief。
2. 含还款计划/担保期间/展期条款 → `renewal-tracker` 登记
   contracts/renewal-register.yaml。
3. 全部引用过 `citation-audit`；条文原文经 `statute-verify` 核验
   （重点：LPR 四倍规则的现行司法解释文本、保证方式推定规则）。
4. 用户需要给业务方看的版本 → `contract-summary`（Quiet mode；上游
   严重度只作下限，降级须声明理由——G9）。
5. 进入多轮谈判或分期履行管理的，提示经 `matter-workspace` 建档，
   后续展期、变更挂同一事项 slug。
6. 审查中发现画像借款立场缺失或覆盖不全的，提示经 `customize` 完善
   playbook——playbook 越完整且经律师审定，未来给出 🟢 的空间越大。
