# 解除/裁员合规评估

## 目的

把「想解除一个人」变成「路径判断 + 成本测算 + 程序核对」：先确定可走
的解除路径，再算经济补偿，再核程序要件，再排禁止解除情形，最后按
🟢🟡🔴 输出风险分级与行动清单。

本技能的核心纪律有四条：

1. **路径决定后果**：不同解除路径的举证责任、补偿成本、程序要求完全
   不同；路径选错，后面全错；
2. **程序瑕疵可独立致违法**：实体理由成立但程序缺失（未通知工会、未
   提前通知），同样构成违法解除风险；
3. **举证责任决定风险归属**：过错解除的举证责任在单位——证据链不
   完整时，「有理由」不等于「能胜诉」；
4. **不做「保证胜诉」结论**：本技能输出风险评估与概率性的利弊分析，
   任何路径都不承诺仲裁/诉讼结果。

本技能遵守 legal-core Shared guardrails（G1–G12）与docs/scenes/labor-cn.md；
冲突时以 legal-core 为准。

## 前置检查

1. 已按docs/scenes/labor-cn.md B1 完成画像检查与路由确认。
2. blocks 红线初扫：是否命中场景 A8.1 blocks——重点是**以孕期、产期、
   哺乳期女职工为对象且缺乏法定解除依据的解除安排**，以及以解除
   安排掩盖拖欠工资、规避社保的目的。命中即停止，按 blocks 纪律
   处理。
3. 升级触发扫描（场景 B5）：群体性裁员、高管、涉工伤、监察已介入、
   外籍员工——命中任一即停止自动推进，生成律师 brief 升级。
4. 利益冲突扫描（G11 + 场景 A6）：是否已为对立方分析过同一解除事项。
5. 事实材料可读：解除通知、劳动合同、规章制度、考核记录等；只有口头
   描述的，在 reviewer note「已读」行写明「基于用户事实描述，未见
   书面材料」。

## 操作规程

### 第 0 步：Matter context（事项上下文）

- 查 `matters/_log.yaml`；已有相关事项的挂到该事项目录下。
- 解除事项几乎必然伴随谈判、仲裁可能，建议经 `matter-workspace` 建档
  （一句提示即可，不强制）。

### 第 1 步：视角与事实采集

确认视角（雇主/员工），并采集最小事实集：

- 谁提出解除、拟用什么理由、是否已发出任何形式的通知；
- 劳动者工龄、月工资水平、合同期限类型；
- 是否涉医疗期、三期（孕期/产期/哺乳期）、工伤、职业病；
- 单位是否有工会、相关规章制度及其民主程序与公示情况；
- 已有证据：考核记录、违纪记录、沟通记录、书面警告等。

事实不全的，把缺项列入 [需复核] 清单，并说明缺项对结论的影响
（G2）；关键事实（是否三期、是否有工会）缺失的，先问再评。

### 第 2 步：解除路径判断树

按以下顺序过判断树，确定可走路径（可同时落在多条路径时，比较成本
与风险）：

1. **协商一致解除**（劳动合同法第三十六条 [模型知识—待核实，引用前
   经 statute-verify 核验]，memo 中正式引用保持 [CITE:__]）：单位
   提出的，应支付经济补偿（第四十六条）；劳动者主动提出的，无
   经济补偿。检查点：解除协议是否书面、补偿数额与支付安排、是否
   附「放弃一切争议」条款及其效力风险 [模型知识—待核实]。
2. **劳动者过错解除**（第三十九条）：试用期被证明不符合录用条件；
   严重违反规章制度；严重失职、营私舞弊造成重大损害；同时与其他
   单位建立劳动关系对本职工作造成严重影响或经提出拒不改正；因
   法定情形致劳动合同无效；被依法追究刑事责任。单位无需支付经济
   补偿。检查点：理由与证据一一对应、规章制度依据有效（民主程序
   + 公示，见 `employee-handbook-review`）、「严重」程度在制度
   层面可识别。**举证责任在单位**，证据链不完整即按高风险处理。
3. **无过错解除**（第四十条）：医疗期满后不能从事原工作也不能从事
   另行安排的工作；不能胜任工作经培训或调岗仍不能胜任；客观情况
   发生重大变化致合同无法履行且协商不成。应提前 30 日书面通知或
   额外支付 1 个月工资，并支付经济补偿（第四十六条）。检查点：
   「不能胜任」需有考核与培训/调岗记录闭环；「客观情况重大变化」
   的认定口径从严 [模型知识—待核实]。
4. **经济性裁员**（第四十一条 [模型知识—待核实，引用前经
   statute-verify 核验]）：法定人数门槛、优先留用人员、六个月内
   重新招用时的优先招用义务、提前向工会或全体职工说明并向劳动
   行政部门报告的程序。命中群体性事项的按场景 B5 升级。
5. **劳动者被迫解除**（第三十八条）：单位未按约定提供劳动保护或
   条件、未及时足额支付报酬、未依法缴纳社保、规章制度违法损害
   权益等情形下，劳动者可解除并主张经济补偿（第四十六条）——
   员工视角的常用主动路径；雇主视角下这是「被动风险点」，评估
   单位是否存在这些过错。
6. **违法解除的后果**：无法定依据或程序违法解除的，劳动者可主张
   继续履行，或主张赔偿金（经济补偿标准的二倍）（第四十八条、
   第八十七条 [模型知识—待核实，引用前经 statute-verify 核验]，
   memo 中正式引用保持 [CITE:__]）。

### 第 3 步：经济补偿计算（N / N+1 / 2N）

按第四十六条先确认是否应付、再按第四十七条计算（memo 中正式引用
保持 [CITE:__]）：

| 形态 | 适用 | 计算规则 |
| --- | --- | --- |
| N | 协商一致（单位提出）、无过错解除、被迫解除、裁员等 | 每满 1 年支付 1 个月工资；6 个月以上不满 1 年按 1 年算；不满 6 个月支付半个月工资（第四十七条） |
| N+1 | 仅第四十条无过错解除路径 | N + 未提前 30 日通知的代通知金 1 个月工资 [模型知识—待核实] |
| 2N | 违法解除赔偿金 | 经济补偿标准的二倍；与 N 不并计 [模型知识—待核实，引用前经 statute-verify 核验] |

基数与年限细则：月工资按解除前 12 个月平均应得工资（含奖金、津贴
等）[模型知识—待核实]；月工资高于当地上年度职工月平均工资 3 倍的，
按 3 倍封顶且年限最高 12 年（第四十七条）；社平工资数值 [需复核]
当地口径。

输出时给计算框架与试算，不写死最终金额——地方数据未核验的，金额
栏标 [需复核]。

### 第 4 步：程序要件核对

- **通知工会**：单位单方解除（第三十九条、第四十条路径）应事先将
  理由通知工会；单位无工会的，实务上有向所在地工会或职工代表
  告知的替代做法 [模型知识—待核实，引用前经 statute-verify 核验]。
  未通知工会的程序瑕疵可独立导致解除被认定违法 [模型知识—待核实]。
- **提前 30 日书面通知**：仅第四十条路径适用（或以代通知金替代）。
- **裁员程序**：说明情况、听取意见、向劳动行政部门报告（第四十一条
  [模型知识—待核实]）。
- **解除通知本身**：书面、载明理由、送达证据——理由一经通知即固定，
  事后不得补充变更解除理由 [模型知识—待核实]。

### 第 5 步：禁止解除情形排查

逐项排查禁止解除事由（第四十二条 [模型知识—待核实，引用前经
statute-verify 核验]，memo 中正式引用保持 [CITE:__]）：

1. 从事接触职业病危害作业未进行离岗前职业健康检查，或疑似职业病
   病人在诊断或医学观察期间；
2. 患职业病或因工负伤并被确认丧失或部分丧失劳动能力（涉工伤的
   同时触发场景 B5 升级）；
3. 患病或非因工负伤在规定的医疗期内（医疗期长度为地方规则，
   [需复核] 当地口径）；
4. 女职工在孕期、产期、哺乳期；
5. 在本单位连续工作满 15 年且距法定退休年龄不足 5 年 [模型知识—
   待核实]；
6. 法律、行政法规规定的其他情形。

命中任一：第四十条、第四十一条路径关闭；但第三十九条过错解除路径
不受第四十二条限制 [模型知识—待核实，引用前经 statute-verify 核验]。
**特别注意**：用户意图对三期员工找「过错理由」包装解除的，评估证据
真实性——证据不足以支撑真实过错的，按 blocks 精神停止并提供律师
brief，不协助构造理由。

### 第 6 步：风险分级 + 行动清单

- **🔴 不得推进**：命中 blocks；命中禁止解除情形且无真实过错路径；
  证据链明显不足仍拟走过错解除（败诉即 2N 外加恢复劳动关系风险）。
- **🟡 需修订或需人判断**：路径可走但程序要件缺失（可补正）；补偿
  数额超出画像审批底线；证据链有缺口可补强。
- **🟢 可推进**：路径清晰、程序齐备、补偿测算经地方数据核验、证据
  链完整。地方数据未核验的最高 🟡（场景 B3）。
- 每个风险点按 G9 双轴标注。
- 行动清单按时间顺序排列：先补什么证据、先走什么程序、什么时候
  送达、钱什么时候付。

### 第 7 步：输出评估 memo

按下方模板输出。涉及解除通知书、协商解除协议文本起草的，一律
「建议转法务/律师起草」，本技能不代拟。

### 第 8 步：后果门（对应 G5）

- 含 🔴：明示「不推进当前解除方案」，生成「带给律师的一页 brief」，
  非律师用户到此停止。
- 🟢/🟡 且用户为非律师：发出解除通知或签署解除协议前走 G5 动作
  闸门——显式确认知悉后果、获得明确指令、生成律师 brief。
- 员工视角用户：提示仲裁时效风险（劳动争议申请仲裁的时效期间为
  1 年，《劳动争议调解仲裁法》第二十七条），时效临近的立即标 🔴
  并建议尽快咨询律师；需要准备仲裁材料的转 `labor-arbitration-prep`。

### 第 9 步：收尾

- 引用过 `citation-audit`；未核验保持 [CITE:__]，FAIL 不得外发。
- 过程产物按 matter-workspace 版本规则保存。
- 向用户复述后果门结果与下一步，确认其理解。

## 本技能不做什么

- **不做「保证胜诉」「肯定能解除」的结论**——输出是风险评估，不是
  结果承诺。
- 不协助构造或包装解除理由：证据不支撑真实过错的，不帮助把无过错
  解除伪装成过错解除。
- 不代拟解除通知书、协商解除协议——一律「建议转法务/律师起草」。
- 不写死赔偿金额：地方数据未核验的给计算框架，金额标 [需复核]。
- 不处理 blocks 与 B5 升级事项的后续（不出绕行方案）。
- 不覆盖工伤待遇核算、群体性裁员整体方案——命中即升级。
- 不做法律意见陈述：对非律师用户的全部输出受 G5 UPL 门控。

## 收尾与下一步

1. memo 交付后按第 8 步后果门分流。
2. 全部引用过 `citation-audit`；需核验条文原文的经 `statute-verify`。
3. 解除所依据的规章制度未经审查的，提示路由 `employee-handbook-review`
   ——制度无效则过错解除路径坍塌。
4. 员工视角用户拟主张权利的，转 `labor-arbitration-prep` 准备仲裁
   材料，并优先核对时效。
5. 协商解除谈成后涉及新文本签署的，提示可路由 `labor-contract-review`
   审查解除协议。
6. 事实或地方标准核验后取得的新立场，建议经 `customize` 写回画像。
