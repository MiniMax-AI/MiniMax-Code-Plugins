# 规章制度 / 员工手册审查

## 目的

把一份规章制度从「内容读起来合理」变成「程序 + 内容双重有效」：劳动
领域铁律是——**直接涉及劳动者切身利益的规章制度，未经民主程序与公示
告知的，不能作为用工管理与违纪解除的依据**。本技能先核程序、再核
内容、再核与劳动合同的冲突，输出三色分桶 memo 与补正流程建议。

本技能的核心纪律有三条：

1. **程序先于内容**：内容再合理的制度，没有民主程序与公示证据，在
   解除案件中就是一堆废纸；
2. **制度是解除的弹药库**：过错解除（劳动合同法第三十九条「严重违反
   规章制度」）的胜败往往不在员工行为，而在制度本身是否有效、
   「严重」是否在制度层面可识别；
3. **补正只面向未来**：程序补正能救将来的管理动作，救不了已经发生
   的解除——历史个案按场景 B5 提示咨询律师。

本技能遵守 legal-core Shared guardrails（G1–G12）与docs/scenes/labor-cn.md；
冲突时以 legal-core 为准。

## 前置检查

1. 已按docs/scenes/labor-cn.md B1 完成画像检查与路由确认。
2. blocks 红线初扫（场景 A8.1）：用户意图借制度修订掩盖拖欠工资、
   规避社保或针对三期员工的，停止并按 blocks 纪律处理。
3. 用途确认：新建制度 / 既有制度补正 / 拟依制度作违纪解除前的有效性
   核查——第三种用途下，个案事实与证据问题提示同步加载
   `termination-assessment`。
4. 文本完整可读；制度版本与修订历史不明的，在 reviewer note「已读」
   行写明。
5. 利益冲突扫描（G11 + 场景 A6）。

## 操作规程

### 第 0 步：Matter context（事项上下文）

- 查 `matters/_log.yaml`；制度修订通常伴随多轮讨论与公示动作，建议
  经 `matter-workspace` 建档（一句提示即可，不强制）。

### 第 1 步：民主程序要件核查

直接涉及劳动者切身利益的规章制度或重大事项（劳动报酬、工作时间、
休息休假、劳动安全卫生、保险福利、职工培训、劳动纪律、劳动定额
管理等），应当依法经以下程序（劳动合同法第四条，memo 中正式引用
保持 [CITE:__]）：

1. **讨论**：经职工代表大会或者全体职工讨论，提出方案和意见
   [模型知识—待核实，引用前经 statute-verify 核验]；
2. **协商确定**：与工会或者职工代表平等协商确定 [模型知识—待核实]。

核查证据链（逐项问用户要，要不到的列入 [需复核] 并说明后果）：

- 职工代表大会或全体职工会议的通知、签到表、会议纪要、讨论意见
  记录；
- 与工会或职工代表协商的记录（意见书、答复、修改对照稿）；
- 无工会、无职工代表大会的小微企业：全体职工讨论的替代安排与
  证据 [模型知识—待核实]。

程序缺失的后果：制度不能作为确定双方权利义务的依据，违纪解除据此
将被认定违法 [模型知识—待核实]——这是 🔴 级后果，但程序本身可
补正，属 work-but-ships（见第 5 步）。

### 第 2 步：公示告知证据评估

规章制度应公示或告知劳动者（劳动合同法第四条）：

- **常见公示方式与证据力**：培训签到 + 考核、入职签收单、OA/邮件
  系统已读回执、公告栏张贴（配合拍照与见证）[模型知识—待核实]；
- **评估要点**：告知是否覆盖**全体**适用对象（老员工在制度修订后
  是否重新告知）、证据是否可归档调取、电子证据是否有原始载体；
- **修订即重新告知**：制度修订版本未重新公示告知的，对员工不生
  效力风险，🟠 起步；
- 告知证据缺失的：制度在个案中可能不被采信 [模型知识—待核实]，
  属 work-but-ships，可补正（重新公示 + 签收），但补正前不作
  解除依据使用。

### 第 3 步：内容合法性审查

逐章审查制度内容，高频问题：

1. **罚款条款**：企业对员工罚款的权力在法律上存重大争议，主流
   口径持谨慎否定态度 [模型知识—待核实，引用前经 statute-verify
   核验]——建议以绩效考核扣减、依实际损失主张赔偿等替代结构；
   保留罚款表述的，🟠 起步并给替代方向；
2. **违纪解除条款的明确性**：「严重违反规章制度」作为解除依据，
   制度层面必须可识别——行为类型尽量列举（如旷工天数、损失金额
   线）、程度标准尽量客观；只有「情节严重者可解除」而无任何
   量化或列举的，个案认定空间完全交给裁判者，🟡 起步；
3. **与法律强制性规定冲突**：如迟到扣全天工资、离职扣发全部未发
   工资、限制法定休假权利等内容，无效风险 🔴 起步；
4. **过罚相当**：轻微违纪直接顶格解除的条款，个案中被认定不合理
   的风险 [模型知识—待核实]；
5. **兜底条款**：「其他严重违反公司规定的行为」类兜底表述的效力
   不确定性 [模型知识—待核实]——可作补充但不能作唯一依据。

### 第 4 步：与劳动合同的冲突处理

- 制度与劳动合同约定不一致时，劳动者主张按合同约定处理的，可能
  获得支持 [模型知识—待核实，引用前经 statute-verify 核验]；
- 审查动作：把制度中的报酬结构、工时休假、考核与解除条款与在用
  劳动合同模板逐项比对，输出冲突清单；
- 处理建议：统一文本版本管理——制度修订后同步评估合同模板是否
  需要联动更新；冲突不可调和的，提示「建议转法务/律师起草」
  修订方案。

### 第 5 步：三色分桶 + 补正流程建议

- **🔴 不得作为依据使用**：程序与公示证据均缺失，且用户拟立即依
  该制度作违纪解除——此时解除违法风险高，先停止解除动作（联动
  `termination-assessment` 评估）；或内容含明显违法条款（🔴 级
  内容项）。
- **🟡 需补正后使用**：程序或公示证据有缺口可补正；内容有瑕疵
  条款可修订。
- **🟢 可使用**：程序证据链完整、公示覆盖全员、内容合法且明确。
- 每个标记项按 G9 双轴标注。
- **补正流程建议**（🟡/🔴 制度通用）：
  1. 修订文本（内容瑕疵条款先行修订——起草部分「建议转法务/律师
     起草」）；
  2. 重新履行民主程序（职代会或全体职工讨论 + 协商），全程留痕；
  3. 重新公示告知并组织签收/培训考核；
  4. 归档证据（通知、签到、纪要、签收单、系统回执）；
  5. 补正完成前，不以新条款作为解除依据。

### 第 6 步：输出审查 memo

按下方模板输出。制度修订文本起草一律「建议转法务/律师起草」。

### 第 7 步：后果门（对应 G5）

- 含 🔴 且涉及拟解除个案的：明示「当前制度不宜作为解除依据」，
  生成「带给律师的一页 brief」，非律师用户到此停止。
- 用户为非律师且拟发布/修订制度：发布前走 G5 动作闸门——显式
  确认知悉程序要求并获得明确指令。
- 向用户复述补正流程与「补正只面向未来」的边界，确认其理解。

### 第 8 步：收尾

- 引用过 `citation-audit`；未核验保持 [CITE:__]，FAIL 不得外发。
- 过程产物按 matter-workspace 版本规则保存；制度各版本永不覆盖。
- 民主程序与公示证据的归档要求写入 memo，提醒用户制度化执行。

## 本技能不做什么

- 不代拟制度全文或修订稿——需要起草的一律「建议转法务/律师起草」。
- 不保证补正后历史解除行为被追认有效——补正只面向未来；历史个案
  按场景 B5 提示咨询律师。
- 不处理依该制度已发生的解除个案的完整辩护策略（联动
  `termination-assessment` 与律师）。
- 不设硬编码管理标准（旷工几天算严重、损失多少算重大）——给明确性
  原则，具体数值由用户按经营实际确定并承担。
- 不覆盖集体合同谈判、职工代表大会组建方案——属专项，提示咨询
  劳动法律师。
- 不做法律意见陈述：对非律师用户的全部输出受 G5 UPL 门控。

## 收尾与下一步

1. memo 交付后按第 7 步后果门分流。
2. 全部引用过 `citation-audit`；条文核验经 `statute-verify`。
3. 拟依制度解除个案的，联动 `termination-assessment` 评估路径与
   程序。
4. 制度与劳动合同模板冲突的，提示路由 `labor-contract-review`
   审查合同模板联动修订。
5. 补正流程完成后，建议将程序与公示证据归档规则经 `customize`
   写回画像，形成长期资产。
6. 发生依该制度的仲裁案件的，转 `labor-arbitration-prep` 并重点
   准备程序与公示证据。
