# 律师函 / 催告函起草（demand-draft-cn）

## 目的

帮用户把「我要正式催对方」变成一封**站得住、收得回、留得下痕**的函件。
函件一旦发出就是证据：写错了事实是自证其误，写重了语气是授人以柄，发得
没留痕等于没发。所以本技能的重心不在「写」，而在写之前的**七道门**与发
之前的**核对清单**。

三条铁律：

1. **七项 gate 不逐项确认就停止**——不允许「都差不多，先写吧」；
2. **版本永不覆盖**——draft-v1、draft-v2……逐版新文件（与
   matter-workspace 的版本纪律一致），历史版本是过程证据，也是回退路；
3. **非律师使用者发出前必须经执业律师复核**（G5 UPL 门控）——本技能起草
   的是「供律师复核的草稿」，不是可径直发出的成品。

## 前置检查

1. 确认用户角色；非律师用户的草稿头部与 checklist 中必须带「发出前须经
   执业律师复核」的醒目提示（G4/G5）。
2. 关联事项：已有事项的（matters/_log.yaml 中有 slug），草稿与 checklist
   存入该事项 drafts/ 目录；没有的，建议先走 `matter-intake` 建档（函件
   通常伴随后续行动，散落的函件草稿是管理灾难）。用户坚持不建：允许，但在
   reviewer note 中记录「未建事项」。
3. 函件类型初定：催告履行 / 催款 / 解除通知 / 异议主张 / 其他。类型决定
   正文骨架（见操作规程第 2 步）。

## 七项 pre-draft gate（起草前必须逐项确认）

向用户逐条出示以下七项，**逐项得到明确确认**（「确认」或具体修正）后方可
进入起草；任何一项被跳过、含糊或用户表示「不用管」，即停止起草，说明该项
的风险，等待确认：

**Gate ① 事实准确性**

函件中每一个事实陈述都必须有出处：合同第几条、哪天的转账凭证、哪天的
聊天记录。请用户逐项确认事实清单与对应出处；没有出处的事实不进函件。
口述事实在草稿中以「据我方记录」限定，不写成不容置疑的断言。

**Gate ② 承认风险**

函件措辞不得构成本方的不利承认。逐句检查草稿语料：不写「我方也有迟延」
之类自我归责表述；对己方履行情况的描述限定在「与本案主张直接相关且属实」
的最小范围；金额主张与既有对账一致，不在函件中首次承认任何扣减。请用户
确认：函中每个关于本方的陈述，都经得起在法庭上被念出来。

**Gate ③ 时效影响**

催告函可能产生诉讼时效中断的效果（权利人向义务人提出履行请求
[模型知识—待核实，引用前经 statute-verify 核验]）。向用户确认：本函是否
有中断时效的意图；如有，函中必须有明确的「要求履行」表述与具体请求内容，
且发送留痕（见 Gate ⑦）必须能证明「到达对方」。时效状态本身存疑的
（matter-intake 中有 [需复核] 旗），起草停止，先由律师核时效。

**Gate ④ 管辖与主体资格**

确认：收函主体全称准确（与合同签约方一致，发到关联方等于没发）；本方
发函主体正确（谁签合同谁发函，母子公司不混用）；如合同有争议解决条款，
函件措辞不与该条款冲突（如约定仲裁的，函中不预告「向法院起诉」）。主体
信息未经核验的，提示先查（企业信用信息公示系统），核验后确认。

**Gate ⑤ 语气**

全函专业克制：陈述事实、援引条款、提出请求、告知后果，四件事说清楚即可。
不威胁（不写与合法权利无关的施压内容）、不夸大（不写没有依据的损失数字）、
不情绪化（零感叹号标准）。请用户确认接受该语气标准；用户要求「写狠一点」
的，说明过度措辞的反噬风险（构成骚扰、损害商誉的反索赔空间），仍坚持的
停止起草，建议直接找律师。

**Gate ⑥ 保密过滤**

函件不泄露本方策略与底线：不写「只要你方还 X 我们就撤」之类底线暴露；
不写内部决策过程；不附送对方尚未掌握的证据原件信息（引用证据写明名称与
日期即可，细节庭上见）。涉商业秘密内容，确认收函对象范围。请用户确认函中
信息「被对方拿给任何人看都没关系」。

**Gate ⑦ 发送方式与留痕**

发送前确定送达方案：EMS 邮寄（备注栏写明函件名称，如「关于 XX 合同第 X
条的催告函」），保留面单与妥投记录；合同约定送达地址与通知条款的，按约定
地址发送并核对条款要求的形式（书面/专人/邮件）；辅助渠道（邮件、微信）可
并行但不替代留痕主渠道。请用户确认送达地址与方式。

## 操作规程

### 第 1 步：过七项 gate

逐项出示、逐项确认、逐项记录确认结果（confirmations 写入 checklist.md）。
任何一项未确认 → 停止，不进入起草。

### 第 2 步：起草 v1

按函件类型选骨架：

```markdown
# <催告函/律师函/解除通知>（草稿 v<N>，供律师复核）

致：<收函方全称>
自：<本方全称>
日期：<留空，签发日填写>
事由：<合同名称及编号，第 X 条相关事宜>

一、事实
<仅 Gate ① 确认过的事实，按时间顺序，每条带出处>

二、依据
<合同条款原文摘录；法条引用保持 [CITE:__] 占位，由律师核验后填实>

三、请求
<明确、具体、可执行：金额/行为/期限
（如"请于收函后 N 日内支付……"）>

四、后果告知
<克制陈述权利保留："我方保留依据合同及法律规定进一步主张权利的
一切权利">
```

- 语气执行 Gate ⑤ 标准；法条一律 [CITE:__] 占位，不以模型记忆填条文号
  （G10）。
- 内部工作版（含 reviewer note、gate 确认记录）与外发版分离：**外发版不得
  带任何内部标头、reviewer note、gate 记录**——外发版是干净函件本身。

### 第 3 步：聊天内迭代

- 用户反馈修改意见 → 出新版本 `draft-v<N+1>.md`，**永不覆盖旧版**；
- 每版头部记录：版本号、相对上一版的改动点、改动发起人；
- 任何修改把已确认的 gate 项推翻的（如改了事实陈述），对应 gate 重新确认。

### 第 4 步：定稿与 checklist

用户认可某版后，生成 `checklist.md`（发送前核对清单，见输出模板），与该版
草稿一并交付。非律师用户：明确告知「**发出前须经执业律师复核**」，checklist
第一项即律师复核签字位（G5：该提示不得省略、不得弱化、不得被「仅供参考」
一类措辞稀释）。

### 第 5 步：发出后（用户告知已发出时）

- 在事项 notes.md 记录发送日期、方式、单号（外发事实记录，与
  matter-workspace 的外发登记一致）；
- 提示：复函、电话沟通均做书面记录；对方回应可能构成新的证据或时效事由
  [模型知识—待核实]；
- 提示登记后续跟进日期（如函中给的履行期限届满日）。

## 输出模板

`checklist.md`：

```markdown
# 发函前核对清单：<事由>（draft-v<N>）

- [ ] 执业律师已复核定稿（非律师使用者必填；复核人：______ 日期：______）
- [ ] Gate ① 事实逐项有出处，出处原件在手
- [ ] Gate ② 全文无本方不利承认表述（复核人逐句确认）
- [ ] Gate ③ 时效意图与"要求履行"表述一致；留痕方案可证明到达
- [ ] Gate ④ 收函主体与发函主体全称核对无误；与争议解决条款无冲突
- [ ] Gate ⑤ 语气通读：无威胁、无夸大、无情绪化表述
- [ ] Gate ⑥ 无策略/底线/未披露证据泄露；涉密内容范围确认
- [ ] Gate ⑦ 送达地址核对（合同约定地址优先）；EMS 备注栏拟写：______
- [ ] 外发版已剥离全部内部标头与过程记录
- [ ] 法条引用已由律师核验填实（无 [CITE:__] 残留）
- [ ] 签署/用印按画像「印章与签署流程」完成
- [ ] 发送后面单、妥投记录归档至事项目录
```

## 本技能不做什么

- **不替律师签发**：以律师事务所名义出具的「律师函」只能由执业律师签发；
  本技能起草的文本是供律师复核采用的草稿，不仿造律师函格式与签章。
- **不过门就写**：七项 gate 未逐项确认，一起草请求即拒绝。
- **不填条文号**：法条一律 [CITE:__] 占位，由律师核验填实（G10）。
- **不覆盖版本**：任何修改出新版，旧版永久保留。
- **不让内部信息上外发版**：外发版不带内部标头、reviewer note、gate 记录。
- **不承诺函件效果**（「发了对方就会还钱」式预期管理不做）；不做威胁性
  措辞。
- **非律师场景不豁免律师复核**：UPL 门控不可协商（G5）。

## 收尾与下一步

1. 交付：定稿 draft-v<N>.md（内部版 + 外发版）+ checklist.md，说明
   「checklist 全部打勾前不要发出」。
2. 非律师用户：再次明示律师复核义务，可按 G5 整理「带给律师的一页 brief」
   （事项背景、函件目的、gate 确认记录、时间敏感性）。
3. 发出后：notes.md 记录送达证据；跟进日期登记（可挂 matter 提醒）。
4. 对方回应或期限届满无回应的：建议携全部版本与送达记录咨询律师，评估
   下一步（诉讼/仲裁路径回到 `matter-intake` 登记新阶段，经
   `matter-workspace` update 挂同一 slug）。
