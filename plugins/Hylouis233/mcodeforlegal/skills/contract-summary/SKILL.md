# 合同要点一页纸（业务方版本）

## 目的

把法律语言写成的合同，翻译成业务方能直接用的行动指引：这份合同是干什么
的、我们要做什么、钱和时间怎么安排、最该担心的三件事是什么、下一步干
什么。读者是没有法律背景的业务同事或管理层，所以本技能的全部纪律围绕
一件事：**让读的人三分钟内知道自己该做什么，且不被误导**。

本技能是 Quiet mode（docs/scenes/contract-review-cn.md A2）的代表场景：成稿里没有任何
「我怎么做的」，只有「你要什么、注意什么」。

## 前置检查

1. **上游结论优先**：通常在 contract-review / nda-review / sales-contract-review
   的审查 memo 之后调用，直接复用 memo 的结论与标记项；不重复做一遍法律
   审查。
2. **无上游 memo 时**（用户直接拿合同来要摘要）：先按 `contract-review` 路由器走完
   审查流程，再出摘要——摘要不能建立在没审过的文本上。
3. **角色与去向确认**：读者是谁（业务/管理层/相对方）；给相对方看的版本
   另行按对外口径处理，本技能默认读者是本方业务侧。
4. **红线守门**：审查结论是 🔴 的，摘要的「建议动作」只能是「暂缓签署、
   已请律师介入」方向，不得出现「可以签」的任何措辞。

## 操作规程

### 第 1 步：取数

从审查 memo 取四类素材：

- 合同基本事实：双方、标的、金额、期限、主要商业安排；
- 本方核心权利义务：从 memo 通过项与结构对照中提炼，每条一句平实的话；
- 钱与时间节点：付款节点、交付节点、账期、质保金、合同期限、续约/终止
  窗口（contracts/renewal-register.yaml 里已登记的日期优先采用）；
- 风险：从 memo 标记项里选**最多三个**对业务影响最大的，按对业务的影响
  排序，不按法律技术严重性排序。

### 第 2 步：翻译（法律语言 → 平实语言）

翻译规则：

- 能写「我们」就不写「买受人/甲方/本方」——除非文本里甲方乙方另有其人
  且会混淆；
- 每条风险用「如果……就会……」的因果句式，不用「或然性」「瑕疵」
  「抗辩」这类词。
  - 不说：「验收条款存在默示验收风险。」
  - 说：「货到了如果我们 3 天内没提出书面异议，法律上就等于验收合格了，
    之后再发现质量问题会很难办。」
- 金额、日期、比例写具体数字，不写「按合同约定」；
- 法条引用一律不进正文；确需交代依据的，在页脚一行写明「本摘要基于合同
  文本与适用法律整理，具体条款以合同原文为准」。

### 第 3 步：成稿（一页纸，五段）

按下方输出模板成稿，总长控制在一页纸（约 400–600 字正文）。五段缺一
不可：

1. **这份合同是什么**：一句话说清和谁、做什么、多少钱、多长时间；
2. **我们要做什么 / 对方要做什么**：本方核心权利义务与对方核心义务，
   各列三到五条；
3. **钱和时间**：节点表（什么时间点、谁付谁、多少钱、附带什么条件）；
4. **三个最大风险**：最多三个，平实因果句式，每个后面跟一句「我们可以
   怎么办」；
5. **建议动作**：明确、可执行、带责任指向——「可以走签署流程」「先改
   第 X 条再签」「暂缓，已请律师看」三选一为主，不写模棱两可的
   「请酌处」。

### 第 4 步：元叙述剥离（Quiet mode 检查）

成稿后通读一遍，删除以下内容：

- 「我读取了哪些文件」「我使用了什么技能/工具」「作为 AI 助手」之类过程
  叙述；
- 「根据第 X 步检查」「按 playbook 第 X 项」之类内部流程语言；
- 审查技能的内部术语（三色分桶、blocks、playbook）——业务版只说人话；
- 但**保留**：G4 保密标头、reviewer note 五行块（这是格式要件，不是元
  叙述）。

语言标准：通读时问自己——「这读起来像不像我们法务同事写的？」任何暴露
自动化痕迹的句子都要改写。

### 第 5 步：与 memo 一致性核对

- 摘要的「建议动作」必须与上游 memo 的三色结论一致：🔴 → 暂缓方向；
  🟡 → 先改后签方向；🟢 → 可走签署流程方向（非律师场景仍带「建议律师
  过目」——G5 提示不得省略、不得弱化）。
- 上游 memo 中标记项的严重度在本摘要中只能作为**下限**；如因翻译简化
  显得变轻，必须恢复或显式声明降级理由（G9）。
- 摘要不得出现 memo 里没有的事实与数字；拿不准的回到合同原文核对，核对
  不了的不写。
- 摘要不得弱化 memo 中的 🔴 项；可以少写（只挑三个），不可以洗白。

### 第 6 步：交付

- 保密标头按读者角色对应 G4 档位；非律师读者带「研究备忘」标头。
- 交付时附一句口头说明：这是一页纸摘要，完整审查意见在内部 memo，签字前
  以 memo 为准。

## 反例对照（Quiet mode 改前改后）

- 改前：「我已完整阅读合同全文及三个附件，并使用买卖合同审查清单进行了
  逐项比对，发现以下问题……」
  改后：「这份合同里最需要注意的是三件事。」
- 改前：「根据 playbook 第 4 项账期立场，该条款被分为 🟡。」
  改后：「对方要 180 天账期，比我们通常能接受的长不少，建议谈到 90 天
  以内再签。」
- 改前：「作为 AI，我无法提供法律意见。」
  改后：不写这句话——限制已由 G4 标头与页脚一行承担，正文中不出现。

## 本技能不做什么

- 不做独立法律审查——摘要复用上游 memo 结论，不自己另审一遍、不产出与
  memo 不同的结论。
- 不在正文引用法条、不堆法律术语——需要法律深度的读者去看内部 memo。
- 不列超过三个风险——一页纸承载力有限，其余风险在 memo 里。
- 不弱化 🔴 结论；memo 结论不允许时，绝不出「可以签」的措辞。
- 不制作给相对方看的版本（对外版本需另行按对外口径审查后制作）。
- 不写「请酌处」式无结论收尾——必须给明确建议动作。

## 收尾与下一步

摘要末尾的决策树：

```text
建议动作
├─ 可以走签署流程
│   → 按画像「印章与签署流程」要求用印
│   → 含期限/续约条款 → 确认 renewal-register 已登记
│   → 非律师用户仍建议：签署前请律师过目一次（G5）
├─ 先改再签
│   → 把「三个最大风险」里的修改点反馈给起草方/相对方
│   → 改完回来复审（走 contract-review 路由器）
└─ 暂缓，已请律师看
    → 不向相对方承诺任何时间表
    → 「带给律师的一页 brief」已生成，等律师意见
```

交付后：

1. 用户反馈业务侧有追问的，回到内部 memo 找依据，不在业务版里临时加法律
   论证。
2. 合同实际签署或条款修订后，提示更新 renewal-register 与 matter 记录。
3. 摘要本身如被转发到保密圈外，提醒用户按 Destination check 的口径处理
   （必要时出脱敏再版）。
