# cold-start-interview：执业画像访谈

## 目的

本插件的所有技能都依赖 docs/guardrails.md 中的执业画像来决定行为档位（保密标头、UPL 门控、
法域锚定、数据源选择、红线提示）。画像缺失时，技能只能按最保守档位运行，体验
和保护都不完整。

本技能通过一次结构化访谈完成画像，把使用者的回答以**散文**写回 docs/guardrails.md，使
后续所有技能"开机即认识使用者"。

访谈同时承担一次数据源凭证体检：哪些源可用、哪些缺 token，直接写进画像，避免
后续检索时才发现覆盖缺口。

## 前置检查

1. 读取`docs/guardrails.md`，定位"执业画像"章节；
2. 检查画像中 `[填空]` 的分布：
   - 全部为空 → 首次访谈，按模式参数走完整流程；
   - 部分已填 → 询问使用者是补全剩余项还是 `--redo` 全部重谈；
   - 全部已填 → 告知画像已完成，提示用 `customize` 做局部修改，除非使用者
     明确要求 `--redo`；
3. 检查是否存在上次中断留下的 `[PENDING]` 标记（写在 docs/guardrails.md 画像章节末尾），
   有则优先询问是否续谈；
4. 若参数为 `--check-integrations`，跳过访谈，直接进入第 6 步的凭证体检并输出
   报告，不改动画像其他内容。

## 操作规程

### 1. 确定访谈模式

- `quick`（默认推荐给时间紧的使用者）：6 问，约 3 分钟，覆盖最低可用画像——
  角色、法域、行业、常做业务、红线（至少一条，可填"暂无"）、数据源有无；
- `full`：20 问，覆盖画像全部九个字段，约 10-15 分钟；
- `--redo`：清空画像全部内容（保留章节结构），按 `full` 重谈；执行前必须显式
  确认，因为会丢弃已有画像；
- 无参数：先问使用者选 quick 还是 full，并说明两者差别。

### 2. 提问顺序与问题清单

按以下顺序逐组提问，每组问完可以追问澄清，但不要一次抛出全部问题（访谈不是
问卷轰炸）：

**第一组 身份与法域（full 为第 1-4 问，quick 合并为 2 问）**

1. 您的身份是执业律师、企业法务、合规人员、业务人员，还是学生/其他？
   （追问：执业律师的话，所在机构与主要执业领域？非律师的话，所在部门与
   汇报线？）
2. 用一句话描述您日常的工作形态，例如"我每天审销售合同"或"我做诉讼为主"。
3. 您的工作法域是中国大陆吗？是否经常处理涉港澳台或涉外业务？
4. （涉外的追问）主要涉及哪些法域、什么类型的业务？

**第二组 业务面（full 为第 5-8 问，quick 合并为 2 问）**

5. 您所在的行业是什么？
6. 日常涉及哪些业务领域（公司治理、劳动人事、数据合规、知识产权、投融资、
   争议解决等）？
7. 您最高频处理的三到五种合同或法律文件类型是什么？
8. 有没有"一看就头大"的高频坑（既往踩过或被提醒过的条款类型）？

**第三组 底线与升级（full 为第 9-13 问，quick 合并为 1 问）**

9. 您的红线条款有哪些？出现什么条款时必须提示您？
10. 有没有需要升级审批的事项（金额阈值、担保、关联交易等）？
11. 遇到不同类型的问题时，您一般找谁？（按劳动争议、重大合同、刑事线索、
    监管问询等场景分别问）
12. 您所在组织的用印与签署流程是怎样的？
13. 您个人在文件上签字前，习惯做哪些核对？

**第四组 数据源与偏好（full 为第 14-20 问，quick 合并为 1 问加自动体检）**

14. 您有没有北大法宝账号？（有则指引：设置 PKULAW_SERVICE_ID 与 PKULAW_TOKEN
    后运行 scripts/enable_pkulaw.py 完成启用）
15. 有没有聚法或其他商业库账号？
16. 是否需要美国法对照检索（CourtListener，免费）？
17. 您的输出语言偏好（中文/英文/中英对照）？
18. 偏好的格式（简洁清单式/标准报告式/详细备忘录式）？
19. 详细程度偏好（只看结论/结论加理由/完整论证过程）？
20. 还有什么希望我记住的工作习惯？

### 3. 中断与续谈

- 使用者中途离开（说"先到这里""待会继续"或长时间未答）时，把已收集的回答
  先写回 docs/guardrails.md 对应字段，未完成的字段保留 `[填空]`，并在画像章节末尾
  追加一行：`[PENDING] 访谈中断于第 N 组第 M 问，下次续谈从这里开始`；
- 续谈时读取该标记，从断点继续，不重复已答问题；
- 全部完成后删除 `[PENDING]` 标记。

### 4. 写回 docs/guardrails.md

- **写散文，不写 YAML**：把回答组织成自然语言段落，填进画像各小节的
  `[填空]` 位置。保留使用者原话中有信息量的措辞（如"我们老板最讨厌仲裁
  条款"应写成"使用者明确表示不接受仲裁条款"这类忠实改写），不要压缩成
  干巴巴的字段值；
- 不确定或使用者说"随便/都可以"的字段，写"使用者未特别限定，按通用默认
  处理"，不要把 `[填空]` 留在原地；
- 写回前向使用者复述一遍关键档位："按您的回答，您是非律师使用者，后续
  产物会带研究备忘标头，签字/发送前我会要求显式确认"，确认无误再写入；
- 写回时更新文件顶部与本技能相关的复核日期（如适用）。

### 5. 角色定档

写回后显式告知使用者其画像决定的 guardrails 档位：

- **执业律师档**：产物头部 `【保密·内部法律分析】`；不启用 UPL 动作闸门；
- **非律师档**：产物头部 `【研究备忘——不构成法律意见，使用前请经执业律师
  复核】`；签字/发送/提交/付款前必须显式确认并生成一页 brief。

### 6. 凭证体检（含 --check-integrations 模式）

逐项检查并在画像"常用数据源与凭证配置"小节记录：

1. `PKULAW_TOKEN` 环境变量是否存在且非空（只检查存在性，不打印 token 本身，
   不尝试真实调用计费接口）；
2. 聚法凭证是否存在（按 `references/connectors.yaml` 中登记的 env 名检查）；
3. flk（内置免费源）：运行一次 `flk_check`（如 MCP 已挂载）或说明"内置源，
   无需凭证"，网络不可达时如实记录"本次体检未能连通"；
4. CourtListener：免费源，无需凭证，标注"可用，仅限美国法对照"；
5. 体检结论写入画像（例如"2026-08-18 体检：北大法宝未配置，聚法未配置，
   flk 可用"），未配置的源同时口头提示配置方法（指向
   `references/connectors.yaml`）。

### 7. 收尾引导

访谈完成后，按使用者的主要场景给出下一步：

- 常做合同审查 → 引导使用 `contract-review`（如已安装）；
- 常做诉讼与争议 → 引导使用 `litigation-cn`（如已安装）；
- 有在手事项 → 引导用 `matter-workspace` 建立事项工作台；
- 提醒：画像以后可随时用 `customize` 修改，数据源变化后建议重跑
  `--check-integrations`。

## 输出模板

访谈完成时的确认输出：

```
✅ 执业画像已完成
- 使用者：{角色一句话}
- 法域：{默认法域}{涉外说明}
- 档位：{执业律师档 / 非律师档}（保密标头：{标头全文}）
- 红线：{N} 条已登记
- 数据源：{可用列表}；未配置：{列表}
- 下一步：{按场景的建议}
```

凭证体检报告（--check-integrations）：

```
数据源体检（{日期}）
| 数据源 | 状态 | 说明 |
| --- | --- | --- |
| flk（内置） | 可用 / 本次未连通 | 无需凭证 |
| 北大法宝 | 已配置 / 未配置 | env: PKULAW_TOKEN |
| 聚法 | 已配置 / 未配置 | env: 见 connectors.yaml |
| CourtListener | 可用 | 免费，仅美国法 |
```

## 本技能不做什么

- 不给任何法律问题的答案，访谈中使用者顺带问的法律问题应记下并引导到
  `legal-research`；
- 不验证 token 的计费有效性（不做真实付费调用），只检查存在性；
- 不打印、不复制、不外传任何 token 内容；
- 不替使用者决定红线内容，只追问与记录；
- 不修改 Shared guardrails 正文（那是 `customize` 的职责范围，且修改
  guardrails 属于高影响变更）。

## 收尾与下一步

- 画像写回后，删除 `[PENDING]` 标记，确认 docs/guardrails.md 画像章节无残留 `[填空]`；
- 告知使用者：画像修改走 `customize`；法规环境大变后建议复核画像中数据源
  与业务领域；
- 按第 7 步的场景引导结束访谈，不主动展开新任务。
