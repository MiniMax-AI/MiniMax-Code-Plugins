# 决议合规审查（股东会 / 董事会）

## 目的

把一份决议从「看内容对不对」扩展为「程序 + 内容 + 效力后果」的完整
核查：从召集程序走到签字存档，逐环核对，最后按不成立 / 可撤销 / 无效
的三分框架评估瑕疵后果，给出补正建议。

本技能的核心纪律有三条：

1. **程序先于内容**：内容合法的决议，程序瑕疵照样可能被撤销或不成立；
   审查顺序不可颠倒，也不可因「结果大家都同意」跳过程序核查；
2. **瑕疵后果三分**：不成立、可撤销、无效的法律构成与救济路径不同，
   不得混写「决议有问题」一笔带过 [CITE:__]；
3. **补救不包装**：可补正的瑕疵给补正路径；但倒签日期、伪造签名、
   虚构出席的「补救包装」命中场景 A8.1 blocks 第 3 项，立即停止——
   本技能只修复诚实瑕疵，不制造虚假外观。

本技能遵守 legal-core Shared guardrails（G1–G12）与docs/scenes/corporate-cn.md；
冲突时以 legal-core 为准。决议瑕疵三分（无效/可撤销/不成立）的具体
条号、通知期限与表决比例的数字，正文出现处标 [模型知识—待核实，引用前
经 statute-verify 核验]，对外产物中的正式引用一律 [CITE:__] 占位后
核验（G10）。

## 前置检查

1. 已按docs/scenes/corporate-cn.md B1/B2 完成：画像检查（B9 关键项无 [填空]）、路由
   确认（用户已认可走决议审查路径）。
2. 场景类型已确认：**会前审查**（决议草案尚未通过）还是**会后复查**
   （决议已作出）——会后复查额外核查存档与签署实况。
3. 已调取：现行章程（决议规则以章程与法律双层为准）、会议通知记录、
   签到与表决记录、决议文本；缺哪份在 reviewer note「已读」行如实
   写明。
4. 用户角色已识别，决定 G4 标头档位与 G5 后果门口径。

## 操作规程

### 第 1 步：决议事项定性

- 识别决议机关（股东会/董事会/监事会）与决议事项；
- 按事项分类：**普通决议事项**还是**特别决议事项**——修改章程、增加
  或减少注册资本、公司合并分立解散、变更公司形式等属特别决议事项
  [CITE:__]；章程另有更高比例要求的从章程；
- 事项是否属于该机关的法定/章程职权范围：越权决议单独列项；
- 涉关联交易的，核对关联股东/董事回避表决要求 [模型知识—待核实，
  引用前经 statute-verify 核验]。

### 第 2 步：召集程序核查

- **召集权人**：由谁召集（董事会/董事长/监事会/符合条件股东自行
  召集），顺位是否合法 [CITE:__]；
- **通知期限**：股东会会议通知距召开日的天数是否符合法律与章程
  （章程可另有规定或全体股东另有约定）[模型知识—待核实，引用前经
  statute-verify 核验]；董事会通知方式与期限按章程核对；
- **通知方式与内容**：送达对象是否全体、方式是否可证明送达（书面/
  邮件/章程约定方式）、是否载明会议议题——未列入通知的临时议题
  表决，程序风险标 [需复核]；
- **未通知个别股东**：单独列项，法律风险轴不低于 🟠——未被通知
  股东的撤销权有特殊保护规则 [模型知识—待核实]。

### 第 3 步：出席与法定人数核查

- 出席股东所持表决权、出席董事人数是否达到法律与章程要求；
- 委托出席的授权手续（授权委托书、权限范围）；
- 通讯表决、书面决议（传签）是否符合章程允许的表决方式
  [模型知识—待核实]；
- 出席人数或表决权数未达法定/章程要求而作出决议的，可能构成
  决议不成立 [CITE:__]，法律风险轴 🔴。

### 第 4 步：表决比例核查

- 逐项决议核对同意表决权数是否达到所需比例：
  - 普通决议事项：按法律与章程要求的比例 [CITE:__]；
  - 特别决议事项：按法定特别比例 [CITE:__]；
  - 章程约定更高比例的，从章程核对；
- 关联回避后的基数计算是否正确（回避情形下分母是否相应扣减）
  [模型知识—待核实]；
- 同意数不足法定/章程比例的，可能构成决议不成立 [CITE:__]，
  法律风险轴 🔴。

### 第 5 步：签字与存档核查（会后复查场景）

- 决议文本签署情况：主持人、出席董事/股东签字或盖章是否符合法律
  与章程要求；会议记录的制作与签名 [CITE:__]；
- 决议与会议记录、通知、表决票的归档完整性；
- **发现倒签、补签造假、签名伪造迹象的：立即停止**，按场景 A8.1
  blocks 第 3 项处理——说明命中点与后果，建议转执业律师，不提供
  包装方案。

### 第 6 步：瑕疵后果评估（三分框架）

对发现的每项程序或内容瑕疵，按三分框架归类并说明救济路径
[CITE:__]：

1. **无效**：决议内容违反法律、行政法规——自始无效，任何利害关系
   人可主张；
2. **可撤销**：召集程序、表决方式违反法律/章程，或内容违反章程——
   有除斥期间限制（自决议作出之日起的法定期限内起诉；未被通知
   股东的起算规则不同）[模型知识—待核实，引用前经 statute-verify
   核验]；期间经过后撤销权消灭；
3. **不成立**：未召开会议、未表决、出席数或同意数不足等根本程序
   缺失 [CITE:__]。

每项瑕疵给：归类 + 构成理由 + 救济/补正路径 + 时间敏感性（除斥
期间的紧迫性单独标红提示）。

### 第 7 步：补正建议（仅限诚实瑕疵）

- 可补正情形（A8.1 work-but-ships）：通知方式瑕疵但实质到会的、
  签署遗漏的、存档不全的——给补正路径（重新履行程序、补充签署、
  补建档案、必要时重新作出决议）；
- 对效力风险高的决议，建议按法定程序**重新召开会议作出新决议**，
  而不是修补旧文本；
- 补正建议带建议时限；涉除斥期间的，时限从紧并标注计算起点
  [需复核]。

### 第 8 步：输出审查表与后果门（对应 G5）

- 结论含 🔴（不成立/无效风险、blocks 命中）：首页明示「**本决议
  不作为行动依据**」，按 G5 生成「带给律师的一页 brief」，非律师
  用户到此停止；决议效力争议可能进入诉讼的，触发场景 B5 升级。
- 结论 🟢/🟡 且将据决议行动（变更登记、签署文件）：非律师用户走
  G5 动作闸门——显式确认知悉后果并获得明确指令，生成律师 brief。
- 按下方模板输出审查表。

## 本技能不做什么

- 不提供倒签、补签造假、虚构出席的任何方案——命中 blocks，拒绝并
  明示后果。
- 不代拟决议文本与会议文件——需要起草的一律「建议转法务/律师起草」。
- 不混写瑕疵后果：无效、可撤销、不成立分别评估，依据分别标注。
- 不凭记忆写期限与比例：通知期限、表决比例、除斥期间一律核验后
  引用，未核验保持 [CITE:__] 占位。
- 不替代工商变更登记程序判断：决议有效不等于登记完成，登记要求
  以登记机关为准，标 [需复核]。
- 不处理 🔴 事项的后续（生成律师 brief 后停止）。
- 不直接手改画像：现场取得的信息经 `customize` 写回。

## 收尾与下一步

1. 审查表交付后按第 8 步后果门分流：🔴 停止并升级；🟡 补正后复核；
   🟢 走 G5 显式确认 + 律师 brief。
2. 决议事项涉章程修订 → 接续 `company-charter-review`；涉增减资、
   出资催缴 → 接续 `capital-contribution`；涉股东协议执行（委派
   董事等）→ 回查 `shareholder-agreement-review` 的治理条款。
3. 全部引用过 `citation-audit`；决议及附件（通知、签到、表决票、
   记录）提示按法定要求归档留存。
4. 会前审查通过的，提示按核查表逐项留存会议证据——程序合规靠
   档案证明，不靠记忆。
5. 除斥期间临近的瑕疵决议，时间敏感性单独提示用户与律师，避免
   权利期间经过。
