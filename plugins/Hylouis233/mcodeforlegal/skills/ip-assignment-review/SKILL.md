# IP 归属 / 转让条款审查

## 目的

把 IP 条款从「一句话带过」变成「归属、范围、对价、生效四问闭环」：
谁的权利、覆盖哪些成果、给多少钱、什么时候生效。本技能可独立审查
IP 协议，也可嵌入 `contract-review` 处理主交易合同中的知识产权
章节。

本技能的核心纪律有四条：

1. **视角先行**：归属条款对委托方是资产获取、对受托方是资产流失，
   不先定视角就无权下结论；
2. **默认规则是谈判的底牌**：法律对职务成果、委托/合作开发设有
   默认归属规则——知道默认归谁，才知道约定的分量；默认规则
   [模型知识—待核实] 一律经 statute-verify 后才写入正式产物；
3. **背景与前景不分是最大暗坑**：只约定「成果归甲方」而不区分
   既有 IP 与新成果，履行中必然起争议；
4. **登记/公告是生效或对抗要件**：专利、商标转让未经官方程序
   不生效力 [模型知识—待核实，引用前经 statute-verify 核验]——
   合同签了不等于权利过户。

本技能遵守 legal-core Shared guardrails（G1–G12）与docs/scenes/ip-cn.md；冲突时以 legal-core 为准。

## 前置检查

1. 已按docs/scenes/ip-cn.md B1 完成画像检查与路由确认；从
   `contract-review` 嵌入调用的，沿用其画像检查结论。
2. blocks 红线初扫（场景 A8.1）：条款安排意在掩盖侵权来源（如把
   明知来自第三方保密信息的成果「洗」为受托方成果再转让），停止
   并按 blocks 纪律处理。
3. 升级触发扫描（场景 B5）：高价值 IP 组合交易、IP 出资/质押、
   职务发明归属有争议迹象、涉外转让（技术进出口管制衔接）——
   命中即升级。
4. 文本范围确认：完整合同还是仅 IP 章节；仅章节的，提示主交易
   结构（买卖/服务/开发）影响条款解释，在 reviewer note「已读」
   行写明。
5. 利益冲突扫描（G11）。

## 操作规程

### 第 0 步：Matter context（事项上下文）

- 查 `matters/_log.yaml`；IP 交易通常多轮谈判，建议经
  `matter-workspace` 建档（一句提示即可，不强制）。

### 第 1 步：视角确认

确认本方角色：委托方 / 受托方 / 合作方 / 雇主 / 员工 / 转让方 /
受让方 / 许可方 / 被许可方。角色决定检查重心：

- **拿钱买成果的一方**（委托方、受让方）：关注归属是否完整、
  背景 IP 是否被搭售许可、前景改进归谁、登记生效是否落实；
- **出力做成果的一方**（受托方、员工、许可方）：关注背景 IP
  是否被无偿卷走、署名权等人身权是否保留、对价与后续改进
  的自由度。

### 第 2 步：职务成果归属核对（合同法 × 劳动法交叉）

涉及员工或前员工完成成果的，核对两条默认规则线 [模型知识—
待核实，引用前经 statute-verify 核验]，memo 中正式引用保持
[CITE:__]：

1. **职务发明创造（专利法线）**：执行本单位的任务或者主要是
   利用本单位的物质技术条件所完成的发明创造，申请专利的权利
   属于该单位 [模型知识—待核实]；单位对完成人有奖励与报酬
   义务 [模型知识—待核实]；
2. **职务作品（著作权法线）**：一般职务作品著作权归作者，单位
   有业务范围内优先使用权；主要利用单位物质技术条件创作并由
   单位承担责任的特定类型作品（如图纸、软件等），作者享有
   署名权，其他权利归单位 [模型知识—待核实]。

审查要点：

- 合同中对「职务成果」的定义是否被不当扩大（如把员工离职后、
  与单位任务无关的成果也罩进来）——员工视角 🟠 起步；
- 是否落实奖励报酬安排——雇主视角下缺失是合规缺口 🟡；
- **交叉提示**：职务成果条款常与劳动合同、保密协议、竞业限制
  联动，涉劳动关系部分提示路由 `labor-cn` 审查。

### 第 3 步：委托开发与合作开发归属

核对默认规则与约定空间 [模型知识—待核实，引用前经 statute-verify
核验]，memo 中正式引用保持 [CITE:__]：

1. **委托开发**：无约定或约定不明的，研发人取得申请专利的权利
   ——委托方出钱不一定买到权属，**约定优先**，委托方视角下
   「未约定归属」是 🔴 级缺口；委托方通常享有实施权与优先
   受让安排 [模型知识—待核实]；
2. **合作开发**：无约定时申请专利的权利共有；一方转让共有申请
   权时他方有优先受让权；一方放弃申请的他方可单独申请，放弃
   方可免费实施 [模型知识—待核实]；
3. **约定审查**：归属约定是否明确（归谁、共有时的行使规则、
   对外许可的收益分配）、后续改进成果归属是否单独约定。

### 第 4 步：现有 IP 与前景 IP 区分

- **背景知识产权**：各方在合作前已有的 IP——是否清单化（附件
  列明）；未清单化的，履行中「哪些算背景」必起争议，🟠 起步；
- **前景知识产权**：履行中新产生的成果——归属、申请费用承担、
  维护责任是否明确；
- **交叉许可安排**：一方使用他方背景 IP 实施前景成果的，许可
  范围、期限、是否免费是否写明；
- **改进成果**：对前景 IP 的后续改进归谁、是否回授（grant-back）
  ——独占性回授条款对改进方的创新激励影响重大，双方视角分别
  提示。

### 第 5 步：对价与生效要件

- **对价**：转让/许可费结构（一次性、提成、里程碑）、税费承担、
  与归属条款的对价匹配性；对价约定比照画像审批底线，无硬编码
  阈值；
- **生效与对抗要件** [模型知识—待核实，引用前经 statute-verify
  核验]：专利申请权、专利权转让自登记之日起生效；注册商标
  转让经核准公告后生效；著作权转让以书面合同为准；专利实施
  许可备案的对抗效力 [模型知识—待核实]；
- **审查动作**：条款是否约定办理官方程序的义务、时限与费用
  承担；只写「合同签订即转让」而未安排登记/公告的，受让方
  视角 🟠 起步；
- **涉外提示**：向境外主体转让技术可能涉及技术进出口管理
  [模型知识—待核实]，命中即触发场景 B5 升级与 G3 法域识别。

### 第 6 步：三色分桶 + 输出 memo

- **🟢 可推进**：归属明确、背景/前景区分清楚、对价与生效安排
  闭环、符合本方立场；
- **🟡 需修订或需人判断**：归属缺口可经补充条款补救、默认规则
  未经 statute-verify 核验、对价超画像底线待批；
- **🔴 不得推进**：命中 blocks；权属来源有重大瑕疵；委托方视角
  下「全额付款但权属归对方且无实施权」级别的不对等且不可改。
- 每个标记项按 G9 双轴标注（法律风险 🔴🟠🟡🟢 × 商业摩擦
  阻碍/拖慢/费解/无感）。
- 按下方模板输出 memo；条款修订起草一律「建议转法务/律师起草」。

### 第 7 步：后果门（对应 G5）

- 含 🔴：明示「不进入签署流程」，生成「带给律师的一页 brief」，
  非律师用户到此停止。
- 🟢/🟡 且用户为非律师：签署前走 G5 动作闸门——显式确认知悉
  后果并获得明确指令，生成律师 brief。
- 向用户复述结论与下一步，确认其理解。

### 第 8 步：收尾

- 引用过 `citation-audit`；未核验保持 [CITE:__]，FAIL 不得外发。
- 过程产物按 matter-workspace 版本规则保存。
- 嵌入 `contract-review` 使用的，将本 memo 的严重度结论回传
  主审查——主 memo 引用时只能作下限，降级须声明理由（G9）。

## 本技能不做什么

- 不代拟 IP 条款或修订稿——需要起草的一律「建议转法务/律师
  起草」。
- 不做 IP 价值评估（估值、作价入股定价属评估机构与谈判事项）。
- 不设硬编码对价标准——商业判断比对画像审批底线。
- 不处理侵权诉讼、无效程序的实体对抗——命中即按场景 B5 升级。
- 不覆盖技术进出口合规细节——命中涉外即升级并触发 G3。
- 不凭模型记忆写默认规则进对外产物——默认规则经 statute-verify
  后方可填入正式引用（G10）。
- 不做法律意见陈述：对非律师用户的全部输出受 G5 UPL 门控。

## 收尾与下一步

1. memo 交付后按第 7 步后果门分流。
2. 全部引用过 `citation-audit`；条文核验经 `statute-verify`。
3. 涉劳动关系的职务成果条款，提示路由 `labor-cn` 审查劳动侧。
4. 条款定稿签署后涉及登记/公告手续的，提示经 `matter-workspace`
   记入事项节点跟踪办理期限。
5. 拟申请专利/软著的，分别路由 `patent-disclosure-review` /
   `software-copyright` 准备申请材料。
6. 归属安排与审批底线的结论建议经 `customize` 写回画像复用。
