# due-diligence：法律尽职调查编排器

## 目的

法律尽职调查的形态是：**以交易目的为导向，对目标公司的法律状况做系统性核查，
把发现按严重度分层，交给决策者一份能据此行动的报告**。人工做这件事的痛点是
领域遗漏与发现失焦；模型做这件事的最大风险是把「没看到的资料」说成「没有问题」。

本技能是**编排器**：它不重复 `tabular-review` 的网格规则（每格三件套、四表
契约、「未见」纪律）与 `matter-workspace` 的台账规则（登记簿、版本、证据目录），
而是把它们串成一条尽调流水线，并在网格之上加两件事：**按目的裁剪问题清单**、
**把 Flags 归总成有行动指向的尽调报告**。

本技能严格遵守 docs/guardrails.md Shared guardrails（G1 来源标注、G2 禁止静默补充、
G3 法域识别、G4 保密标头、G6 内容信任、G8 可恢复优先、G9 双轴严重度、
G10 引用纪律、G11 利益冲突）。法条与案例引用一律先 `[CITE:__]` 占位，
经 `statute-verify` / `case-verify` 核验后填入；不确定的制度描述标
`[模型知识—待核实，引用前经 statute-verify 核验]`。

## 前置检查

1. **画像完成度**：读取 docs/guardrails.md 执业画像，确认无 `[填空]`；有则停止并引导
   先跑 `cold-start-interview`。确认使用者角色，确定 G4 标头档位。
2. **尽调目的先定**：开工前必须明确本次尽调目的——**投资 / 并购 / 合作 /
   合规自查**。目的决定核查深度与侧重（裁剪指引见
   `references/diligence-checklist.md` 末节）。使用者没说清的，先问清楚再
   开工：给投资方做的股权尽调与给收购方做的全量尽调，清单、深度、报告侧重
   完全不同，目的不明就跑网格必然返工。
3. **立场与利益冲突（G11）**：确认委托方是谁（投资方 / 收购方 / 合作方 /
   目标公司自身）。发现本事项此前已为利益对立一方做过分析的，立即停止并
   提示冲突审查。
4. **保密义务提示**：资料室（data room）资料通常受保密协议或保密承诺约束。
   开工时向使用者提示一次：尽调资料与发现不得向交易对方以外传播；产物按
   G4 标头管理，标头随文保留；资料原件进 `evidence/` 后只进不出。
5. **法域判断（G3）**：默认锚定 cn-mainland；目标公司涉外商投资、境外架构、
   跨境资产的，显式声明法域判断并先查 `LEGAL_FRAMES/`，无基线的按 G3 第三
   步说明缺口。

## 操作规程

### 第 1 步：matter-workspace intake 建档

- 调 `matter-workspace` 新建事项，`type: due-diligence`；登记当事人（委托方、
  目标公司）、来源（谁交办的）、关键日期——排他期截止、签约目标日、交割日、
  监管审批申报期等时效类节点必须登记进 intake.md「时效提醒」；
- 资料室目录或清单一式登记进 `evidence/`（只进不出），在 notes.md 记录
  资料来源与收到日期；
- 本步骤的目录约定、登记簿格式、版本规则均由 `matter-workspace` 定义，
  本技能不重复。

### 第 2 步：按目的裁剪问题清单（确认门）

- 以 `references/diligence-checklist.md` 的分域问题库为底稿，按尽调目的
  裁剪：保留领域、删除不适用问题、按目标公司所属行业增补行业特有问题
  （画像「行业与业务领域」有对应监管规则的，并入「诉讼与合规」领域）；
- 画像「红线条款与审批底线」对应的红线类问题**不得被裁剪**，一律并入清单；
- **确认门**：把裁剪后的清单（保留哪些领域、删了哪些问题、理由是什么）
  完整提交使用者确认，取得明确确认后才进入下一步。路由与范围未经确认不
  推进——确认门之前不得开始读资料、跑网格。

### 第 3 步：资料清单请求（document request list）

- 按确认后的问题清单反向生成**资料请求清单**：逐项列出需要目标公司/资料室
  提供的文件（如章程及历次修正案、验资报告、前十大客户合同、社保缴纳凭证、
  商标注册证等），每项标注三态：**已提供 / 缺失 / 不适用**；
- 缺失项分两档：
  - **影响结论**——无该资料，对应领域只能出「未见」结论（如验资报告缺失，
    出资实缴只能记「未见」）；
  - **可后补**——不阻断本轮核查，列入报告「缺口与假设声明」；
- 收到的资料逐份登记进 `evidence/` 并在 notes.md 追加：`{日期} 收到
  {文件名}，来源 {谁提供}，对应清单项 {编号}`。

### 第 4 步：调 tabular-review 执行网格

- 以资料目录为文档集、确认后的问题清单为问题集，调 `tabular-review` 执行
  N 文档 × M 问题网格；
- 网格纪律全部由 `tabular-review` 定义并执行：每格三件套（value/_source/
  status）、提取不到填「未见」、超过 10 份文档先试点 3 份确认格式、XLSX
  四表契约（无 XLSX 依赖时降级 CSV 四件套）、Verified 列留给人工签核；
- 读不了的资料（加密、扫描件无 OCR、格式损坏）如实登记 unread 清单，
  不跳过、不假装读过（G2）。

### 第 5 步：Flags 分级汇总

收拢 `tabular-review` 的 Flags 表，做两层归总：

1. **双轴严重度排序（G9）**：法律风险 🔴🟠🟡🟢 × 商业摩擦 阻碍/拖慢/费解/
   无感，法律风险降序优先、同级按商业摩擦降序；下游报告引用 Flags 时严重度
   只作**下限**，降级须显式声明理由；
2. **红线项三段式归桶**：
   - **blocks（命中即停）**：按现状交易做不成或不得推进——如主体资格瑕疵
     （吊销、注销）、核心业务无必备特许资质、核心资产权属不清且无法补正、
     股权被冻结且无法解除。停止推进，说明命中点与依据（或依据的不确定性），
     按画像升级矩阵移交，不提供「如何绕过」的方案；
   - **work-but-ships（可补救）**：附整改建议与建议时限——如社保欠缴可补缴、
     决议程序瑕疵可补正、商标类别缺类可补申请 [模型知识—待核实，具体补救
     路径引用前经 statute-verify 核验]；
   - **FYI（记录不扩大）**：非典型但合法的安排、偏离惯例但不违法的商业
     条款，仅记录，不主动升级为风险项。

### 第 6 步：尽调报告成稿（quiet mode）

- 按下方「输出模板」成稿。**quiet mode**：报告不携带元叙述——不出现「我读取
  了哪些文件」「我调用了什么技能」「作为 AI 我……」一类过程表述；G4 标头、
  reviewer note 五行块与 `[CITE:__]` 占位是格式要件，不是元叙述；
- 报告默认是**内部工作成果**，发给委托方决策层；拟发给交易对方或投资机构
  的版本，另行与使用者确认范围后单独成稿。

### 第 7 步：citation-audit 门禁（发出前提）

- 报告中的法条/案例引用保持 `[CITE:__]` 占位，经 `statute-verify` /
  `case-verify` 核验通过后填入正式引用；严禁编造条文号、案号（G10）；
- 报告发出前必须过 `citation-audit`，FAIL 状态不得发出；时间紧就缩小引用
  范围，只保留已核验的引用。

## 本技能不做什么

- **不下投资结论**：报告回答「法律上有什么、风险在哪、怎么承接」，不回答
  「该不该投/该不该买」——交易决策属于使用者及其客户；
- **不做财务/税务尽调**：报表真实性、审计调整、税务测算与筹划另聘会计师/
  税务师；本技能只覆盖财务事项的**法律根源**（重大资产权属、抵押担保、
  或有负债的合同根源），并在报告中显式声明这一边界；
- **不替代律师现场核查**：访谈管理层、实地查验、向登记机关/监管机关调档等
  动作由执业律师执行，本技能只生成核查清单与待办；
- **不评估商业前景**：市场规模、技术先进性、团队竞争力不在范围内；
- **不重复库技能规则**：网格规则归 `tabular-review`，台账与版本规则归
  `matter-workspace`，检索与核验归 `legal-research` / `statute-verify` /
  `case-verify`，本技能只做编排与法律定性汇总；
- **不把未过 citation-audit 的报告对外发出**（G10）。

## 收尾与下一步

1. **Flags 转事项待办**：把 Flags 表转成该事项 notes.md 的待办条目并登记
   跟进日期（`matter-workspace` update）；blocks 项同时按画像升级矩阵处理，
   严重度下限 🟠；
2. **版本永不覆盖**：报告成稿存 `drafts/<报告名>-v1.md`，后续修订递增版本
   号；已对外发出的版本永不覆盖、永不改名；
3. **外发登记**：在 notes.md 记录每次外发——`{日期} 外发 {文档名}-v{N}
   给 {对象}，方式 {邮件/平台}，citation-audit 结果 {PASS}`；
4. 报告中引用的高频变动法规（`references/currency-watch.md` 清单内）提醒
   记录核验日期；
5. 尽调衍生的新事项（如发现未决诉讼需单独立项跟踪）提示用
   `matter-workspace` 新建事项，并在两边 notes 互相关联 slug；
6. 交割后仍有跟进事项的（整改承诺、证照补办），提示可转入在办事项清单
   持续跟进，并定期对照相关法规更新。
